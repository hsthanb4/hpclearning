核心心智模型

1. 为什么纯文本大模型同构 5D 并行在具身 VLA 中彻底失效？

在大语言模型（LLM）分布式训练中，全网所有 Transformer 层的结构完全一致，整个集群可以划分成规整同构的 5D 并行网格： World Size=DP×TP×PP×CP×EP\text{World Size} = \text{DP} \times \text{TP} \times \text{PP} \times \text{CP} \times \text{EP}

但在具身智能视觉-语言-动作（VLA）模型（如 Physical Intelligence π0\pi_0、OpenVLA、RT-2）以及端到端智驾模型中，模型由两个结构截然不同的子网络拼接而成：

  1. 视觉编码器（Vision Encoder, 如 ViT / SigLIP）：
    • 特点：参数量较小（300M∼1B300\text{M} \sim 1\text{B}），但输入分辨率极高（例如 6 路环视相机，产生数千个图像 Patch Tokens）；
    • 计算特征：属于双向非因果注意力（Non-Causal Attention），序列短而密集，单步计算极快，计算瓶颈在于前向激活值显存占用；
  2. 语言/动作解码器（Language-Action Backbone, 如 LLaMA / Diffusion Action Transformer）：
    • 特点：参数量巨大（7B∼70B7\text{B} \sim 70\text{B}），承担复杂任务逻辑理解与动作去噪；
    • 计算特征：因果自注意力或多步连续动作去噪，计算复杂度极高，必须拆分张量并行（TP）与流水线并行（PP）才能装下显存。

如果强行将整个模型套用统一的并行配置（如全网强制 TP=4\text{TP}=4）： - 视觉编码器参数量仅几百兆，切分成 4 份后每个 GPU 上的局部矩阵极小，在 NVLink 上频繁触发微秒级小包 AllReduce，算力利用率（MFU）直接跌破 20%！ - 视觉部分的激活值显存爆炸，而语言部分却显存闲置，整个集群陷入严重的“木桶短板”。

2. 异构设备网格（Cross-Mesh Topology）与维度失配鸿沟

现代工业级多模态分布式框架（如 Megatron-Core Multimodal、DeepSpeed-Visual）的根本解法是解耦设备网格（Decoupled Device Meshes）：

图 15-1：具身多模态异构双 Mesh 并行拓扑与跨网格张量重构体系

如图 15-1 所示： - 视觉网格（Vision Mesh）：配置为 DPV=8,TPV=1\text{DP}_V = 8, \text{TP}_V = 1。每张卡独立吃下一整张完整的图像，内部没有任何跨卡通信，矩阵乘跑满 Tensor Core； - 语言网格（Language Mesh）：配置为 DPL=2,TPL=4\text{DP}_L = 2, \text{TP}_L = 4。每 4 张卡组成一个 TP 组切分大模型权重。 - 维度失配（Dimensional Mismatch）： - 视觉网格产出的张量形态：GPU ii 持有完整的样本 ii，特征维度为全量的 [BV=1,SV,DV][B_V=1, S_V, D_V]； - 语言网格要求的输入形态：DP 组内要求 4 张卡协同处理同一批样本，但每张卡由于 Column-Parallel 投影层的存在，仅需要特征分片 [BL=4,SV,DLTPL][B_L=4, S_V, \frac{D_L}{\text{TP}_L}]！

必须在视觉与语言交界处，执行一次确定性的张量重排（Cross-Mesh Resharding）！

3. 跨网格通信代数推导与 Projector 切分

设全局批次大小为 BB，视觉序列长度为 SVS_V，视觉隐藏维度为 DVD_V，语言模型隐藏维度为 DLD_L。跨模态多层感知机投影层（Projector）执行线性映射： Xlang=Xvis⋅Wproj,Wproj∈ℝDV×DLX_{\text{lang}} = X_{\text{vis}} \cdot W_{\text{proj}}, \quad W_{\text{proj}} \in \mathbb{R}^{D_V \times D_L}

通信与计算的执行顺序存在两种根本架构设计：

图 15-2：跨 Mesh 投影与通信解耦时序流

通信量定量推导（方案 B 显著优于方案 A）：

通常在 VLA 模型中，DLD_L（如 4096）显著大于 DVD_V（如 1024）。 - 若先在 Vision 卡投影，数据膨胀到 DLD_L，跨卡发送通信量为 B×SV×DL×2 BytesB \times S_V \times D_L \times 2 \text{ Bytes}； - 最优架构（方案 B）：直接在 Vision 卡沿隐藏特征维将 DVD_V 均匀划分为 TPL\text{TP}_L 个分块，通过 All-to-All 发送给对应语言卡的对应 TP Rank，总单向通信量仅为： Vcomm=B×SV×DV×DPV−1DPV×2 BytesV_{\text{comm}} = B \times S_V \times D_V \times \frac{\text{DP}_V - 1}{\text{DP}_V} \times 2 \text{ Bytes} 到达语言卡后，语言卡直接加载切分好的投影层分片 Wproj(i)∈ℝDVTPL×DLTPLW_{\text{proj}}^{(i)} \in \mathbb{R}^{\frac{D_V}{\text{TP}_L} \times \frac{D_L}{\text{TP}_L}}，本地完成矩阵乘即可无缝拼入 Transformer！

思考与问答题

Q1：为什么不在 ViT 内部直接开启 TP=4，而要设计跨 Mesh 通信？请从算力利用率（MFU）与 NVLink 通信量给出定量因果链。

Note参考解析
  1. GEMM 维度失衡导致计算核心严重饥饿： ViT 的隐藏维度 DVD_V 通常在 768∼1024768 \sim 1024 之间。若采用 TP=4\text{TP}=4，每个注意力头与 MLP 内部矩阵的中间维度被切为仅 256256 甚至更小。在 NVIDIA Ampere/Hopper 架构上，Tensor Core 要求矩阵分块（Tiling）至少为 64×6464 \times 64 或 128×128128 \times 128 才能打满流水线。维度过小会导致 SM 活跃度暴跌，GPU 处于严重的 Memory-bound 空转。
  2. 细碎小包通信吞吐坍塌： ViT 包含 24~32 层。若在 ViT 内部做 TP，每层需要执行 2 次 AllReduce 通信，整个 ViT 前向反向产生高达 100+100+ 次小数据量 AllReduce。小数据包传输受限于网络启动延迟（Latency-bound），无法吃满 NVLink 900GB/s 的带宽，通信开销直接吃掉 50% 以上的时间。
  3. 因果链结论： 采用 DPV=8\text{DP}_V=8 让各卡独立跑大 Batch GEMM，不仅单卡 MFU 提升至 60% 以上，而且内部完全没有通信；仅在最后两网格交界处发射单次大包 All-to-All，以极低的单次通信开销换取了计算能效的大幅倍增。

Q2：跨模态投影层（Projector: Linear or Perceiver Resampler）应该部署在 Vision Mesh 还是 Language Mesh？其梯度反向传播通信量有何本质差异？

Note参考解析
  1. 部署在 Language Mesh 是最优解： 投影层的输入维度为 DVD_V（较小，如 1024），输出维度为 DLD_L（较大，如 4096）。 若在 Vision Mesh 部署，投影后特征膨胀 4 倍，前向跨网格传输量激增 4 倍； 若部署在 Language Mesh，投影层可以自然利用语言网格的 TPL=4\text{TP}_L=4 做 Column-Parallel 切分。跨网格只需传输小维度的 DVD_V，并在语言卡本地直接计算局部矩阵乘。
  2. 反向传播通信量差异： 在反向传播时，下游回传的梯度维度为 DLD_L。若投影层在 Language Mesh，语言卡在本地完成反向 GEMM 计算出关于输入的梯度 ∇Xvis\nabla X_{\text{vis}}（维度收缩回 DVD_V）后，再跨网格反向 All-to-All 发回视觉卡。前向与反向在跨网格高速总线上流动的永远是较小的 DVD_V 数据流，将昂贵的跨节点/跨 NVLink 传输开销压缩了近 75%。

Q3：在流水线并行（PP）场景下，Vision Encoder 应该绑定在 Stage 0 还是作为外部独立流水线？如何利用微批次时间差实现 100% 通信隐藏（Overlap）？

Note参考解析
  1. 绑定在 Stage 0 的致命缺陷： 如果将庞大的 ViT 硬塞给流水线 Stage 0，Stage 0 既要跑重负荷的视觉卷积/Attention，又要跑 LLM 第一层，导致 Stage 0 耗时远大于下游 Stage 1..P−1P-1，流水线产生极其严重的非均匀等待气泡（Asymmetric Pipeline Bubbles）。
  2. 外部异步 Prefetch 流水机制： 最佳工程实践是将 Vision Encoder 部署在独立的 GPU 算力池上，或者在同一物理卡上通过双 CUDA Stream 异步交织调度： 当语言模型正在执行第 mm 个微批次的中间层计算时，视觉 Stream 提前异步预计算并发射第 m+1m+1、第 m+2m+2 个微批次的视觉特征。
  3. 零气泡通信隐藏： 视觉重排通信（Cross-Mesh All-to-All）完全隐藏在语言模型当前微批次的自注意力与 FFN 计算时间窗口内。当第 m+1m+1 个微批次正式流入 LLM Stage 0 时，其多模态前置张量已经在目标 GPU 显存内就绪，实现 100% 计算通信重叠。

        前向张量重排实现:
        1. 汇总所有视觉样本: 全局批次大小 B_global = sum(B_v)
        2. 沿通道维将 D_v 均分为 tp_l 块
        3. 分配给 dp_l 个语言 DP 组，每个 DP 组拥有 B_global // dp_l 个样本
        4. 每个 DP 组内部的 tp_l 张卡，分别持有对应的那一份特征分块
        """
        global_tensor = np.concatenate(v_tensors, axis=0)
        B_global, S_v, D_v = global_tensor.shape
        B_l = B_global // self.dp_l
        D_slice = D_v // self.tp_l

        l_tensors = [None] * self.num_gpus
        for dp_idx in range(self.dp_l):
            batch_slice = global_tensor[dp_idx * B_l : (dp_idx + 1) * B_l]
            for tp_idx in range(self.tp_l):
                rank = dp_idx * self.tp_l + tp_idx
                feat_slice = batch_slice[:, :, tp_idx * D_slice : (tp_idx + 1) * D_slice]
                l_tensors[rank] = np.copy(feat_slice)

        return l_tensors

    def backward_reshard(self, l_grads):
        """
        反向梯度转置重排实现:
        1. 按照 dp_l 组和 tp_l 切片在特征轴重新拼合出每个 DP 组的完整特征梯度 [B_l, S_v, D_v]
        2. 拼接所有 DP 组的梯度得到全局样本梯度 [B_global, S_v, D_v]
        3. 沿 Batch 轴切回各视觉卡持有的 B_v 份
        """
        B_l, S_v, D_slice = l_grads[0].shape
        D_v = D_slice * self.tp_l
        B_global = B_l * self.dp_l

        dp_tensors = []
        for dp_idx in range(self.dp_l):
            tp_slices = [l_grads[dp_idx * self.tp_l + tp_idx] for tp_idx in range(self.tp_l)]
            dp_tensor = np.concatenate(tp_slices, axis=2)
            dp_tensors.append(dp_tensor)

        global_grad = np.concatenate(dp_tensors, axis=0)

        B_v = B_global // self.dp_v
        v_grads = []
        for v_rank in range(self.dp_v):
            v_grads.append(np.copy(global_grad[v_rank * B_v : (v_rank + 1) * B_v]))

        return v_grads

## 核心心智模型

### 1. 为什么纯文本大模型同构 5D 并行在具身 VLA 中彻底失效？

在大语言模型（LLM）分布式训练中，全网所有 Transformer 层的结构完全一致，整个集群可以划分成规整同构的 5D 并行网格：
$$\text{World Size} = \text{DP} \times \text{TP} \times \text{PP} \times \text{CP} \times \text{EP}$$

但在具身智能视觉-语言-动作（VLA）模型（如 Physical Intelligence $\pi_0$、OpenVLA、RT-2）以及端到端智驾模型中，模型由两个结构截然不同的子网络拼接而成：

1. **视觉编码器（Vision Encoder, 如 ViT / SigLIP）**：
   - **特点**：参数量较小（$300\text{M} \sim 1\text{B}$），但输入分辨率极高（例如 6 路环视相机，产生数千个图像 Patch Tokens）；
   - **计算特征**：属于双向非因果注意力（Non-Causal Attention），序列短而密集，单步计算极快，计算瓶颈在于前向激活值显存占用；
2. **语言/动作解码器（Language-Action Backbone, 如 LLaMA / Diffusion Action Transformer）**：
   - **特点**：参数量巨大（$7\text{B} \sim 70\text{B}$），承担复杂任务逻辑理解与动作去噪；
   - **计算特征**：因果自注意力或多步连续动作去噪，计算复杂度极高，必须拆分张量并行（TP）与流水线并行（PP）才能装下显存。

如果强行将整个模型套用统一的并行配置（如全网强制 $\text{TP}=4$）：
- 视觉编码器参数量仅几百兆，切分成 4 份后每个 GPU 上的局部矩阵极小，在 NVLink 上频繁触发微秒级小包 AllReduce，**算力利用率（MFU）直接跌破 20%**！
- 视觉部分的激活值显存爆炸，而语言部分却显存闲置，整个集群陷入严重的“木桶短板”。

如**图 15-1** 所示：
- **视觉网格（Vision Mesh）**：配置为 $\text{DP}_V = 8, \text{TP}_V = 1$。每张卡独立吃下一整张完整的图像，内部**没有任何跨卡通信**，矩阵乘跑满 Tensor Core；

- **维度失配（Dimensional Mismatch）**：
  - 视觉网格产出的张量形态：GPU $i$ 持有完整的样本 $i$，特征维度为全量的 $[B_V=1, S_V, D_V]$；
  - 语言网格要求的输入形态：DP 组内要求 4 张卡协同处理同一批样本，但每张卡由于 Column-Parallel 投影层的存在，仅需要特征分片 $[B_L=4, S_V, \frac{D_L}{\text{TP}_L}]$！

必须在视觉与语言交界处，执行一次确定性的**张量重排（Cross-Mesh Resharding）**！

### 3. 跨网格通信代数推导与 Projector 切分

设全局批次大小为 $B$，视觉序列长度为 $S_V$，视觉隐藏维度为 $D_V$，语言模型隐藏维度为 $D_L$。跨模态多层感知机投影层（Projector）执行线性映射：
$$X_{\text{lang}} = X_{\text{vis}} \cdot W_{\text{proj}}, \quad W_{\text{proj}} \in \mathbb{R}^{D_V \times D_L}$$

通信与计算的执行顺序存在两种根本架构设计：

```{mermaid}
sequenceDiagram
    autonumber
    participant V as 视觉网格 (DP_V = 8, TP = 1)
    participant C as 跨网格重排通信 (Cross-Mesh Comm)
    participant P as 投影层 Projector
    participant L as 语言-动作网格 (DP_L = 2, TP_L = 4)

    Note over V,L: 架构方案 A：先在视觉卡投影，再重排发送 (通信量大: B * S_V * D_L)
    Note over V,L: 架构方案 B (最优)：先分发视觉特征，在语言卡做 Column-TP 投影 (通信量小: B * S_V * D_V)

    V->>C: 发射未膨胀的视觉特征分片 (每个样本切为 TP 块)
    C-->>L: All-to-All 路由至对应 DP 组与对应 TP Rank
    L->>P: 本地并行执行 Column-Parallel 矩阵乘 (无需 AllReduce)
    P-->>L: 直接喂入语言模型第一层 Self-Attention
```
<p class="caption" align="center"><em>图 15-2：跨 Mesh 投影与通信解耦时序流</em></p>

#### 通信量定量推导（方案 B 显著优于方案 A）：
通常在 VLA 模型中，$D_L$（如 4096）显著大于 $D_V$（如 1024）。
- 若先在 Vision 卡投影，数据膨胀到 $D_L$，跨卡发送通信量为 $B \times S_V \times D_L \times 2 \text{ Bytes}$；
- **最优架构（方案 B）**：直接在 Vision 卡沿隐藏特征维将 $D_V$ 均匀划分为 $\text{TP}_L$ 个分块，通过 All-to-All 发送给对应语言卡的对应 TP Rank，总单向通信量仅为：
  $$V_{\text{comm}} = B \times S_V \times D_V \times \frac{\text{DP}_V - 1}{\text{DP}_V} \times 2 \text{ Bytes}$$
到达语言卡后，语言卡直接加载切分好的投影层分片 $W_{\text{proj}}^{(i)} \in \mathbb{R}^{\frac{D_V}{\text{TP}_L} \times \frac{D_L}{\text{TP}_L}}$，本地完成矩阵乘即可无缝拼入 Transformer！

## 思考与问答题

### Q1：为什么不在 ViT 内部直接开启 TP=4，而要设计跨 Mesh 通信？请从算力利用率（MFU）与 NVLink 通信量给出定量因果链。
::: {.callout-note collapse="true"}
#### 参考解析
1. **GEMM 维度失衡导致计算核心严重饥饿**：
   ViT 的隐藏维度 $D_V$ 通常在 $768 \sim 1024$ 之间。若采用 $\text{TP}=4$，每个注意力头与 MLP 内部矩阵的中间维度被切为仅 $256$ 甚至更小。在 NVIDIA Ampere/Hopper 架构上，Tensor Core 要求矩阵分块（Tiling）至少为 $64 \times 64$ 或 $128 \times 128$ 才能打满流水线。维度过小会导致 SM 活跃度暴跌，GPU 处于严重的 Memory-bound 空转。
2. **细碎小包通信吞吐坍塌**：
   ViT 包含 24~32 层。若在 ViT 内部做 TP，每层需要执行 2 次 `AllReduce` 通信，整个 ViT 前向反向产生高达 $100+$ 次小数据量 AllReduce。小数据包传输受限于网络启动延迟（Latency-bound），无法吃满 NVLink 900GB/s 的带宽，通信开销直接吃掉 50% 以上的时间。
3. **因果链结论**：
   采用 $\text{DP}_V=8$ 让各卡独立跑大 Batch GEMM，不仅单卡 MFU 提升至 60% 以上，而且内部**完全没有通信**；仅在最后两网格交界处发射**单次大包 All-to-All**，以极低的单次通信开销换取了计算能效的大幅倍增。
:::

### Q2：跨模态投影层（Projector: Linear or Perceiver Resampler）应该部署在 Vision Mesh 还是 Language Mesh？其梯度反向传播通信量有何本质差异？
::: {.callout-note collapse="true"}
#### 参考解析
1. **部署在 Language Mesh 是最优解**：
   投影层的输入维度为 $D_V$（较小，如 1024），输出维度为 $D_L$（较大，如 4096）。
   若在 Vision Mesh 部署，投影后特征膨胀 4 倍，前向跨网格传输量激增 4 倍；
   若部署在 Language Mesh，投影层可以自然利用语言网格的 $\text{TP}_L=4$ 做 Column-Parallel 切分。跨网格只需传输小维度的 $D_V$，并在语言卡本地直接计算局部矩阵乘。
2. **反向传播通信量差异**：
   在反向传播时，下游回传的梯度维度为 $D_L$。若投影层在 Language Mesh，语言卡在本地完成反向 GEMM 计算出关于输入的梯度 $\nabla X_{\text{vis}}$（维度收缩回 $D_V$）后，再跨网格反向 All-to-All 发回视觉卡。**前向与反向在跨网格高速总线上流动的永远是较小的 $D_V$ 数据流**，将昂贵的跨节点/跨 NVLink 传输开销压缩了近 75%。
:::

### Q3：在流水线并行（PP）场景下，Vision Encoder 应该绑定在 Stage 0 还是作为外部独立流水线？如何利用微批次时间差实现 100% 通信隐藏（Overlap）？
::: {.callout-note collapse="true"}
#### 参考解析
1. **绑定在 Stage 0 的致命缺陷**：
   如果将庞大的 ViT 硬塞给流水线 Stage 0，Stage 0 既要跑重负荷的视觉卷积/Attention，又要跑 LLM 第一层，导致 Stage 0 耗时远大于下游 Stage 1..$P-1$，流水线产生极其严重的非均匀等待气泡（Asymmetric Pipeline Bubbles）。
2. **外部异步 Prefetch 流水机制**：
   最佳工程实践是将 Vision Encoder 部署在独立的 GPU 算力池上，或者在同一物理卡上通过**双 CUDA Stream 异步交织调度**：
   当语言模型正在执行第 $m$ 个微批次的中间层计算时，视觉 Stream 提前异步预计算并发射第 $m+1$、第 $m+2$ 个微批次的视觉特征。
3. **零气泡通信隐藏**：
   视觉重排通信（Cross-Mesh All-to-All）完全隐藏在语言模型当前微批次的自注意力与 FFN 计算时间窗口内。当第 $m+1$ 个微批次正式流入 LLM Stage 0 时，其多模态前置张量已经在目标 GPU 显存内就绪，实现 100% 计算通信重叠。

```python
import numpy as np

class CrossMeshTensorResharder:
    def __init__(self, num_gpus=8, dp_v=8, tp_v=1, dp_l=2, tp_l=4):
        assert dp_v * tp_v == num_gpus, "视觉网格大小必须等于物理卡数"
        assert dp_l * tp_l == num_gpus, "语言网格大小必须等于物理卡数"
        self.num_gpus = num_gpus
        self.dp_v = dp_v
        self.tp_v = tp_v
        self.dp_l = dp_l
        self.tp_l = tp_l

    def forward_reshard(self, v_tensors):
        """
        前向张量重排实现:
        1. 汇总所有视觉样本: 全局批次大小 B_global = sum(B_v)
        2. 沿通道维将 D_v 均分为 tp_l 块
        3. 分配给 dp_l 个语言 DP 组，每个 DP 组拥有 B_global // dp_l 个样本
        4. 每个 DP 组内部的 tp_l 张卡，分别持有对应的那一份特征分块
        """
        global_tensor = np.concatenate(v_tensors, axis=0)
        B_global, S_v, D_v = global_tensor.shape
        B_l = B_global // self.dp_l
        D_slice = D_v // self.tp_l

        l_tensors = [None] * self.num_gpus
        for dp_idx in range(self.dp_l):
            batch_slice = global_tensor[dp_idx * B_l : (dp_idx + 1) * B_l]
            for tp_idx in range(self.tp_l):
                rank = dp_idx * self.tp_l + tp_idx
                feat_slice = batch_slice[:, :, tp_idx * D_slice : (tp_idx + 1) * D_slice]
                l_tensors[rank] = np.copy(feat_slice)

        return l_tensors

    def backward_reshard(self, l_grads):
        """
        反向梯度转置重排实现:
        1. 按照 dp_l 组和 tp_l 切片在特征轴重新拼合出每个 DP 组的完整特征梯度 [B_l, S_v, D_v]
        2. 拼接所有 DP 组的梯度得到全局样本梯度 [B_global, S_v, D_v]
        3. 沿 Batch 轴切回各视觉卡持有的 B_v 份
        """
        B_l, S_v, D_slice = l_grads[0].shape
        D_v = D_slice * self.tp_l
        B_global = B_l * self.dp_l

        dp_tensors = []
        for dp_idx in range(self.dp_l):
            tp_slices = [l_grads[dp_idx * self.tp_l + tp_idx] for tp_idx in range(self.tp_l)]
            dp_tensor = np.concatenate(tp_slices, axis=2)
            dp_tensors.append(dp_tensor)

        global_grad = np.concatenate(dp_tensors, axis=0)

        B_v = B_global // self.dp_v
        v_grads = []
        for v_rank in range(self.dp_v):
            v_grads.append(np.copy(global_grad[v_rank * B_v : (v_rank + 1) * B_v]))

        return v_grads

# 验证执行
num_gpus = 8
dp_v, tp_v = 8, 1
dp_l, tp_l = 2, 4
resharder = CrossMeshTensorResharder(num_gpus=num_gpus, dp_v=dp_v, tp_v=tp_v, dp_l=dp_l, tp_l=tp_l)

S_v, D_v = 16, 128
v_inputs = [np.full((1, S_v, D_v), fill_value=rank, dtype=np.float32) for rank in range(num_gpus)]
l_inputs = resharder.forward_reshard(v_inputs)
assert len(l_inputs) == 8
assert l_inputs[0].shape == (4, 16, 32)
assert np.allclose(l_inputs[0][0, :, :], 0.0)
assert np.allclose(l_inputs[0][3, :, :], 3.0)
assert np.allclose(l_inputs[4][0, :, :], 4.0)

l_grads = [tensor * 2.0 for tensor in l_inputs]
v_grads = resharder.backward_reshard(l_grads)
assert len(v_grads) == 8
for rank in range(8):
    assert v_grads[rank].shape == (1, 16, 128)
    assert np.allclose(v_grads[rank], rank * 2.0)

print("参考实现验证 100% 通过！")
```
