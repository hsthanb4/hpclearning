核心心智模型

1. 均质 1F1B 假设的破灭：具身端到端模型的“哑铃型”算力分布

在标准文本大模型的流水线并行（PP，如第 9 课所示）中，有一个基本假设： 所有流水线阶段的计算耗时严格均等：tf(0)=tf(1)=…=tf(P−1)=tf\text{所有流水线阶段的计算耗时严格均等}：t_f^{(0)} = t_f^{(1)} = \dots = t_f^{(P-1)} = t_f 在此假设下，只要微批次数量 m≫Pm \gg P，气泡率可以被稀释至 P−1m+P−1\frac{P-1}{m + P-1}。

但在具身大模型（如 π0\pi_0、OpenVLA）与自动驾驶端到端模型中，计算负载呈现极端的“两头重、中间轻”（哑铃型分布）：

2. 非均质流水线气泡雪崩的数学推导

在点对点（P2P）阻塞通信约束下，整条流水线的单步节拍被最慢的瓶颈阶段（Bottleneck Stage）强行锁死： tbottle=maxp∈[0,P−1]tf(p)t_{\text{bottle}} = \max_{p \in [0, P-1]} t_f^{(p)}

中间的快速阶段即使很快完成了本地计算，由于下游 Stage P−1P-1 尚未处理完毕，或者上游 Stage 0 尚未吐出新的微批次，中间卡必须进入强制硬件空闲等待（Forced Idle Stalls）。

非均质气泡率（Asymmetric Bubble Ratio）定量公式：

设共有 PP 个流水线阶段，每个阶段前向耗时为 tf(p)t_f^{(p)}，微批次数量为 mm。 整个流水线处理 mm 个微批次稳态流动的理想有用总功为： Wuseful=m∑p=0P−1tf(p)W_{\text{useful}} = m \sum_{p=0}^{P-1} t_f^{(p)} 而整个集群实际消耗的墙上时间（Wall-clock Time）由启动开销与瓶颈阶段节拍决定： Twall≈∑p=0P−1tf(p)+(m−1)⋅tbottleT_{\text{wall}} \approx \sum_{p=0}^{P-1} t_f^{(p)} + (m - 1) \cdot t_{\text{bottle}} 因此，集群的真实非均质气泡率为： Bubbleasym=1−WusefulP⋅Twall=1−m∑p=0P−1tf(p)P⋅(∑p=0P−1tf(p)+(m−1)maxptf(p))\text{Bubble}_{\text{asym}} = 1 - \frac{W_{\text{useful}}}{P \cdot T_{\text{wall}}} = 1 - \frac{m \sum_{p=0}^{P-1} t_f^{(p)}}{P \cdot \left(\sum_{p=0}^{P-1} t_f^{(p)} + (m - 1) \max_p t_f^{(p)}\right)}

结论：即使微批次数量 m→∞m \to \infty，稳态气泡率极限也无法降为 0，而是收敛至： limm→∞Bubbleasym=1−tf¯tbottle\lim_{m \to \infty} \text{Bubble}_{\text{asym}} = 1 - \frac{\overline{t_f}}{t_{\text{bottle}}} 若瓶颈阶段耗时是平均耗时的 2 倍，集群将永久损失 50% 的理论算力。

3. 系统级破局：非均匀层重平衡求解算法（Layer Re-balancing）

要消灭非均质气泡，工业界的终极方案是打破“每张卡均分 L/PL/P 层”的教条，实行加权非均匀层分配（Weighted Layer Partitioning）：

设全网共 LL 个语言/动作 Transformer 骨干层，每个层的前向耗时为 τ\tau。 - Stage 0 拥有固定的视觉前置开销 TvisT_{\text{vis}}，分配 L0L_0 个 Transformer 层； - Stage pp（中间阶段）分配 LpL_p 个 Transformer 层； - Stage P−1P-1 拥有固定的动作去噪头开销 TactionT_{\text{action}}，分配 LP−1L_{P-1} 个 Transformer 层。

约束条件与优化目标： min{Lp}maxp∈[0,P−1]Tps.t.∑p=0P−1Lp=L,Lp∈ℕ\min_{\{L_p\}} \max_{p \in [0, P-1]} T_p \quad \text{s.t.} \quad \sum_{p=0}^{P-1} L_p = L, \quad L_p \in \mathbb{N} 通过削减两头阶段的 Transformer 层数、大幅增加中间阶段的层数，使得各 Stage 总耗时实现微秒级完全对齐：T0≈T1≈…≈TP−1T_0 \approx T_1 \approx \dots \approx T_{P-1}，直接将异构气泡率压回传统均质水平。

思考与问答题

Q1：非均匀 Stage 延迟为什么会导致标准 1F1B 中间卡出现大量“隐式停顿（Forced Stalls）”？请从 P2P 阻塞发送给出时序因果分析。

Note参考解析
  1. 点对点通信背压（Backpressure）机制： 在流水线并行实现中（如基于 NCCL Send/Recv 或 PyTorch P2P 通信），如果中间 Stage 1 已经完成了第 mm 个微批次的前向计算，它必须将激活值张量通过 P2P.send 推送给 Stage 2。 若 Stage 2 正在缓慢地计算前一个复杂的微批次，其接收缓冲区尚未释放，Stage 1 的发送操作就会被阻塞在 CUDA Stream 或内核套接字上。
  2. 上游饥饿与下游阻塞的双重夹击： 同时，当 Stage 1 等待下游就绪时，它无法立即开始下一个微批次，因为上游 Stage 0（正在耗时跑庞大的 ViT）还没有吐出第 m+1m+1 个微批次的数据。
  3. 因果链总结： 快速阶段陷入“上游来不及喂数据，下游来不及收数据”的双重闭锁。流水线硬件时钟无法形成平滑的滑动齿轮，大量 SM 周期白白浪费在同步等待上。

Q2：为什么不能通过无限制增加 Micro-batch 数量 mm 来稀释非均匀气泡？请给出 m→∞m \to \infty 时的气泡下限，并说明 1F1B 下激活常驻显存是否随 mm 增长。

Note参考解析
  1. 主要限制是气泡下限，不是显存： 由第 2 节公式，m→∞m \to \infty 时 Bubbleasym→1−tf¯tbottle\text{Bubble}_{\text{asym}} \to 1 - \frac{\overline{t_f}}{t_{\text{bottle}}}。这一项由各 Stage 耗时的不均衡决定，与 mm 无关。以 [30,10,10,20][30, 10, 10, 20] ms 为例，tf¯=17.5\overline{t_f} = 17.5、tbottle=30t_{\text{bottle}} = 30，下限约为 41.7%41.7\%，增大 mm 只能消除充水/排空部分，消除不了这一项；只有层重平衡（第 3 节）才能降低它（详见第 2、3 节）。
  2. 1F1B 下激活显存不随 mm 增长： 前向产出的激活要保存到对应反向完成才释放。在 1F1B 调度中，Stage pp 的在飞微批次数最多为 P−pP - p，与 mm 无关，所以增大 mm 不会导致 OOM。
  3. 显存峰值数学公式（背景）： 每个微批次在单个 Stage 产生的激活值显存占用为： Mact_mb=S×bμ×h×Lstage×(34+5×a⋅Sh) BytesM_{\text{act\_mb}} = S \times b_{\mu} \times h \times L_{\text{stage}} \times \left(34 + 5 \times \frac{a \cdot S}{h}\right) \text{ Bytes} Stage pp 在流水线稳态时的常驻激活值显存为： Mpeak(p)≈min⁡(m,P−p)⋅Mact_mbM_{\text{peak}}^{(p)} \approx \min(m, P - p) \cdot M_{\text{act\_mb}}
  4. 增大 mm 的其他副作用： 固定 bμb_{\mu} 时，全局批次 Bglobal=m×bμ×DPB_{\text{global}} = m \times b_{\mu} \times \text{DP} 会同步增大，可能超出优化器能接受的批次范围；若固定全局批次而减小 bμb_{\mu}，单次 GEMM 变小，算力利用率下降。

Q3：在具身机器人持续学习（Continual Learning / Online RL）场景中，视觉感知与动作决策的频率严重不对齐，如何设计多速率异步流水线（Multi-Rate Asynchronous Pipeline）以规避物理时钟丢帧？

Note参考解析
  1. 时钟解耦与双速率缓冲区（Dual-Rate Buffer）： 视觉环境更新频率通常较低（如相机 20Hz~30Hz），而低层动作执行器与状态反馈频率极高（如力控 100Hz~200Hz）。 在训练端，不能将两个子网络绑定在同频率的同一条同步流水线上，必须引入多速率时空缓存队列： 视觉 Stage 独立以低频更新并在共享内存中维护全局最新的环境潜空间表征（Latent State Token）；动作 Stage 以高频微批次读取最新的 Latent Token 持续进行策略梯度与流匹配训练。
  2. 异步陈旧梯度补偿（Staleness-Aware Compensation）： 由于视觉特征更新慢，高频动作网络反向传播回传给视觉投影层的梯度存在 1~2 个步长的时间滞后（Staleness）。 系统必须在跨阶段边界应用阻尼修正系数： ∇θvisℒ←λΔt⋅∇θvisℒ,λ∈(0.9,1.0)\nabla_{\theta_{\text{vis}}} \mathcal{L} \leftarrow \lambda^{\Delta t} \cdot \nabla_{\theta_{\text{vis}}} \mathcal{L}, \quad \lambda \in (0.9, 1.0) 通过梯度阻尼衰减，既允许高频动作去噪模块保持实时迭代，又防止陈旧梯度引起视觉编码器权重发散，消灭物理执行端的丢帧失控风险。

import numpy as np

class AsymmetricPipelineScheduler:
    def __init__(self):
        pass

    def simulate_1f1b_execution(self, stage_latencies, num_microbatches):
        """
        精确事件驱动模拟非均质流水线前向执行
        stage_end_time[p]: 当前 stage p 刚刚完成上一个任务的时间
        mb_ready_time[m]: 微批次 m 在上一个 stage 刚刚完成并可供当前 stage 使用的时间
        """
        P = len(stage_latencies)
        m = num_microbatches

        # 记录每个 stage 空闲可接新任务的绝对时间戳
        stage_available = [0.0] * P
        # 记录微批次到达各 stage 并可执行的时间
        # mb_ready_for_stage[m][p]: 微批次 m 可以开始在 stage p 执行的时间
        mb_ready = [[0.0] * P for _ in range(m)]

        for mb in range(m):
            for p in range(P):
                # 开始时间必须同时满足:
                # 1. stage p 硬件空闲
                # 2. 上游 stage p-1 产出的数据已到达 (p=0 时无需等待上游)
                data_ready = mb_ready[mb][p] if p == 0 else mb_ready[mb][p]
                start_time = max(stage_available[p], data_ready)
                cost = stage_latencies[p]
                end_time = start_time + cost

                # 更新硬件与数据就绪时间
                stage_available[p] = end_time
                if p + 1 < P:
                    mb_ready[mb][p + 1] = end_time

        # 总墙上时间是 Stage P-1 处理完最后一个微批次的时间
        total_time = stage_available[-1]

        # 统计有用总功与整体气泡率
        useful_work = sum(stage_latencies) * m
        total_cluster_capacity = P * total_time
        bubble_ratio = 1.0 - (useful_work / total_cluster_capacity)

        return total_time, max(0.0, bubble_ratio)

    def solve_optimal_layer_partition(self, total_layers, layer_cost, s0_fixed_cost, s_tail_fixed_cost, num_stages):
        """
        使用贪心负载最小化算法将 total_layers 分配到各 stage
        每个 stage 初始层数为 1 (至少 1 层以保持流水线完整)
        """
        P = num_stages
        fixed_costs = [0.0] * P
        fixed_costs[0] = s0_fixed_cost
        fixed_costs[-1] = s_tail_fixed_cost

        # 初始每卡分 1 层
        layers = [1] * P
        remaining_layers = total_layers - P

        # 每次将 1 层分配给当前总耗时最小的 stage
        for _ in range(remaining_layers):
            current_latencies = [fixed_costs[i] + layers[i] * layer_cost for i in range(P)]
            # 找到当前负载最小的 stage 赋给它一层
            min_idx = int(np.argmin(current_latencies))
            layers[min_idx] += 1

        return layers

# 验证执行

## 核心心智模型

### 1. 均质 1F1B 假设的破灭：具身端到端模型的“哑铃型”算力分布

在标准文本大模型的流水线并行（PP，如第 9 课所示）中，有一个基本假设：
$$\text{所有流水线阶段的计算耗时严格均等}：t_f^{(0)} = t_f^{(1)} = \dots = t_f^{(P-1)} = t_f$$
在此假设下，只要微批次数量 $m \gg P$，气泡率可以被稀释至 $\frac{P-1}{m + P-1}$。

但在具身大模型（如 $\pi_0$、OpenVLA）与自动驾驶端到端模型中，计算负载呈现极端的**“两头重、中间轻”（哑铃型分布）**：

### 2. 非均质流水线气泡雪崩的数学推导

在点对点（P2P）阻塞通信约束下，**整条流水线的单步节拍被最慢的瓶颈阶段（Bottleneck Stage）强行锁死**：
$$t_{\text{bottle}} = \max_{p \in [0, P-1]} t_f^{(p)}$$

中间的快速阶段即使很快完成了本地计算，由于下游 Stage $P-1$ 尚未处理完毕，或者上游 Stage 0 尚未吐出新的微批次，中间卡必须进入强制硬件空闲等待（Forced Idle Stalls）。

#### 非均质气泡率（Asymmetric Bubble Ratio）定量公式：
设共有 $P$ 个流水线阶段，每个阶段前向耗时为 $t_f^{(p)}$，微批次数量为 $m$。
整个流水线处理 $m$ 个微批次稳态流动的理想有用总功为：
$$W_{\text{useful}} = m \sum_{p=0}^{P-1} t_f^{(p)}$$
而整个集群实际消耗的墙上时间（Wall-clock Time）由启动开销与瓶颈阶段节拍决定：
$$T_{\text{wall}} \approx \sum_{p=0}^{P-1} t_f^{(p)} + (m - 1) \cdot t_{\text{bottle}}$$
因此，集群的真实非均质气泡率为：
$$\text{Bubble}_{\text{asym}} = 1 - \frac{W_{\text{useful}}}{P \cdot T_{\text{wall}}} = 1 - \frac{m \sum_{p=0}^{P-1} t_f^{(p)}}{P \cdot \left(\sum_{p=0}^{P-1} t_f^{(p)} + (m - 1) \max_p t_f^{(p)}\right)}$$

**结论**：即使微批次数量 $m \to \infty$，稳态气泡率极限也无法降为 0，而是收敛至：
$$\lim_{m \to \infty} \text{Bubble}_{\text{asym}} = 1 - \frac{\overline{t_f}}{t_{\text{bottle}}}$$
若瓶颈阶段耗时是平均耗时的 2 倍，**集群将永久损失 50% 的理论算力**。

### 3. 系统级破局：非均匀层重平衡求解算法（Layer Re-balancing）

要消灭非均质气泡，工业界的终极方案是**打破“每张卡均分 $L/P$ 层”的教条**，实行**加权非均匀层分配（Weighted Layer Partitioning）**：

设全网共 $L$ 个语言/动作 Transformer 骨干层，每个层的前向耗时为 $\tau$。
- Stage 0 拥有固定的视觉前置开销 $T_{\text{vis}}$，分配 $L_0$ 个 Transformer 层；
- Stage $p$（中间阶段）分配 $L_p$ 个 Transformer 层；
- Stage $P-1$ 拥有固定的动作去噪头开销 $T_{\text{action}}$，分配 $L_{P-1}$ 个 Transformer 层。

约束条件与优化目标：
$$\min_{\{L_p\}} \max_{p \in [0, P-1]} T_p \quad \text{s.t.} \quad \sum_{p=0}^{P-1} L_p = L, \quad L_p \in \mathbb{N}$$
通过削减两头阶段的 Transformer 层数、大幅增加中间阶段的层数，使得各 Stage 总耗时实现微秒级完全对齐：$T_0 \approx T_1 \approx \dots \approx T_{P-1}$，直接将异构气泡率压回传统均质水平。

```python
    s_tail_fixed_cost=s3_fixed,
    num_stages=num_stages
)

assert sum(optimal_layers) == total_layers, "总层数必须守恒等于 32"
# Stage 0 负担最重，分配层数应最少；Stage 1, 2 应分担最多层数
assert optimal_layers[0] < optimal_layers[1], "Stage 0 应该分配更少层以平衡固定开销"
assert optimal_layers[3] < optimal_layers[2], "Stage 3 应该分配少于中间 Stage 的层数"

# 使用平衡后的层数重新计算各 Stage 耗时
balanced_latencies = [
    s0_fixed + optimal_layers[0] * layer_cost,
    optimal_layers[1] * layer_cost,
    optimal_layers[2] * layer_cost,
    s3_fixed + optimal_layers[3] * layer_cost,
]
_, new_bubble_ratio = scheduler.simulate_1f1b_execution(balanced_latencies, m)
assert new_bubble_ratio < bubble_ratio, f"层重平衡后气泡率必须显著下降！原气泡: {bubble_ratio:.2%}, 新气泡: {new_bubble_ratio:.2%}"

print(f"原始异构气泡率: {bubble_ratio:.2%} -> 重平衡后气泡率: {new_bubble_ratio:.2%}")
print("非均质流水线调度与层重平衡求解测试 100% 通过！")
```

## 思考与问答题

### Q1：非均匀 Stage 延迟为什么会导致标准 1F1B 中间卡出现大量“隐式停顿（Forced Stalls）”？请从 P2P 阻塞发送给出时序因果分析。
::: {.callout-note collapse="true"}

#### 参考解析
1. **点对点通信背压（Backpressure）机制**：
   在流水线并行实现中（如基于 NCCL Send/Recv 或 PyTorch P2P 通信），如果中间 Stage 1 已经完成了第 $m$ 个微批次的前向计算，它必须将激活值张量通过 `P2P.send` 推送给 Stage 2。
   若 Stage 2 正在缓慢地计算前一个复杂的微批次，其接收缓冲区尚未释放，Stage 1 的发送操作就会被阻塞在 CUDA Stream 或内核套接字上。
2. **上游饥饿与下游阻塞的双重夹击**：
   同时，当 Stage 1 等待下游就绪时，它无法立即开始下一个微批次，因为上游 Stage 0（正在耗时跑庞大的 ViT）还没有吐出第 $m+1$ 个微批次的数据。
3. **因果链总结**：
   快速阶段陷入“上游来不及喂数据，下游来不及收数据”的双重闭锁。流水线硬件时钟无法形成平滑的滑动齿轮，大量 SM 周期白白浪费在同步等待上。
:::

### Q2：为什么不能通过无限制增加 Micro-batch 数量 $m$ 来稀释非均匀气泡？请给出 $m \to \infty$ 时的气泡下限，并说明 1F1B 下激活常驻显存是否随 $m$ 增长。
::: {.callout-note collapse="true"}

#### 参考解析
1. **主要限制是气泡下限，不是显存**：
   由第 2 节公式，$m \to \infty$ 时 $\text{Bubble}_{\text{asym}} \to 1 - \frac{\overline{t_f}}{t_{\text{bottle}}}$。这一项由各 Stage 耗时的不均衡决定，与 $m$ 无关。以 $[30, 10, 10, 20]$ ms 为例，$\overline{t_f} = 17.5$、$t_{\text{bottle}} = 30$，下限约为 $41.7\%$，增大 $m$ 只能消除充水/排空部分，消除不了这一项；只有层重平衡（第 3 节）才能降低它（详见第 2、3 节）。
2. **1F1B 下激活显存不随 $m$ 增长**：
   前向产出的激活要保存到对应反向完成才释放。在 1F1B 调度中，Stage $p$ 的在飞微批次数最多为 $P - p$，与 $m$ 无关，所以增大 $m$ 不会导致 OOM。
3. **显存峰值数学公式（背景）**：
   每个微批次在单个 Stage 产生的激活值显存占用为：
   $$M_{\text{act\_mb}} = S \times b_{\mu} \times h \times L_{\text{stage}} \times \left(34 + 5 \times \frac{a \cdot S}{h}\right) \text{ Bytes}$$
   Stage $p$ 在流水线稳态时的常驻激活值显存为：
   $$M_{\text{peak}}^{(p)} \approx \min(m, P - p) \cdot M_{\text{act\_mb}}$$
4. **增大 $m$ 的其他副作用**：
   固定 $b_{\mu}$ 时，**全局批次 $B_{\text{global}} = m \times b_{\mu} \times \text{DP}$ 会同步增大**，可能超出优化器能接受的批次范围；若固定全局批次而减小 $b_{\mu}$，单次 GEMM 变小，算力利用率下降。
:::

### Q3：在具身机器人持续学习（Continual Learning / Online RL）场景中，视觉感知与动作决策的频率严重不对齐，如何设计多速率异步流水线（Multi-Rate Asynchronous Pipeline）以规避物理时钟丢帧？
::: {.callout-note collapse="true"}

#### 参考解析
1. **时钟解耦与双速率缓冲区（Dual-Rate Buffer）**：
   视觉环境更新频率通常较低（如相机 20Hz~30Hz），而低层动作执行器与状态反馈频率极高（如力控 100Hz~200Hz）。
   在训练端，不能将两个子网络绑定在同频率的同一条同步流水线上，必须引入**多速率时空缓存队列**：
   视觉 Stage 独立以低频更新并在共享内存中维护全局最新的环境潜空间表征（Latent State Token）；动作 Stage 以高频微批次读取最新的 Latent Token 持续进行策略梯度与流匹配训练。
2. **异步陈旧梯度补偿（Staleness-Aware Compensation）**：
   由于视觉特征更新慢，高频动作网络反向传播回传给视觉投影层的梯度存在 1~2 个步长的时间滞后（Staleness）。
   系统必须在跨阶段边界应用**阻尼修正系数**：
   $$\nabla_{\theta_{\text{vis}}} \mathcal{L} \leftarrow \lambda^{\Delta t} \cdot \nabla_{\theta_{\text{vis}}} \mathcal{L}, \quad \lambda \in (0.9, 1.0)$$
   通过梯度阻尼衰减，既允许高频动作去噪模块保持实时迭代，又防止陈旧梯度引起视觉编码器权重发散，消灭物理执行端的丢帧失控风险。
:::

```python
import numpy as np

class AsymmetricPipelineScheduler:
    def __init__(self):
        pass

    def simulate_1f1b_execution(self, stage_latencies, num_microbatches):
        """
        精确事件驱动模拟非均质流水线前向执行
        stage_end_time[p]: 当前 stage p 刚刚完成上一个任务的时间
        mb_ready_time[m]: 微批次 m 在上一个 stage 刚刚完成并可供当前 stage 使用的时间
        """
        P = len(stage_latencies)
        m = num_microbatches

        # 记录每个 stage 空闲可接新任务的绝对时间戳
        stage_available = [0.0] * P
        # 记录微批次到达各 stage 并可执行的时间
        # mb_ready_for_stage[m][p]: 微批次 m 可以开始在 stage p 执行的时间
        mb_ready = [[0.0] * P for _ in range(m)]

        for mb in range(m):
            for p in range(P):
                # 开始时间必须同时满足:
                # 1. stage p 硬件空闲
                # 2. 上游 stage p-1 产出的数据已到达 (p=0 时无需等待上游)
                data_ready = mb_ready[mb][p] if p == 0 else mb_ready[mb][p]
                start_time = max(stage_available[p], data_ready)
                cost = stage_latencies[p]
                end_time = start_time + cost

                # 更新硬件与数据就绪时间
                stage_available[p] = end_time
                if p + 1 < P:
                    mb_ready[mb][p + 1] = end_time

        # 总墙上时间是 Stage P-1 处理完最后一个微批次的时间
        total_time = stage_available[-1]

        # 统计有用总功与整体气泡率
        useful_work = sum(stage_latencies) * m
        total_cluster_capacity = P * total_time
        bubble_ratio = 1.0 - (useful_work / total_cluster_capacity)

        return total_time, max(0.0, bubble_ratio)

    def solve_optimal_layer_partition(self, total_layers, layer_cost, s0_fixed_cost, s_tail_fixed_cost, num_stages):
        """
        使用贪心负载最小化算法将 total_layers 分配到各 stage
        每个 stage 初始层数为 1 (至少 1 层以保持流水线完整)
        """
        P = num_stages
        fixed_costs = [0.0] * P
        fixed_costs[0] = s0_fixed_cost
        fixed_costs[-1] = s_tail_fixed_cost

        # 初始每卡分 1 层
        layers = [1] * P
        remaining_layers = total_layers - P

        # 每次将 1 层分配给当前总耗时最小的 stage
        for _ in range(remaining_layers):
            current_latencies = [fixed_costs[i] + layers[i] * layer_cost for i in range(P)]
            # 找到当前负载最小的 stage 赋给它一层
            min_idx = int(np.argmin(current_latencies))
            layers[min_idx] += 1

        return layers

# 验证执行
scheduler = AsymmetricPipelineScheduler()
latencies_unbalanced = [30.0, 10.0, 10.0, 20.0]
m = 8
total_time, bubble_ratio = scheduler.simulate_1f1b_execution(latencies_unbalanced, m)
assert total_time >= 280.0
assert bubble_ratio > 0.40

optimal_layers = scheduler.solve_optimal_layer_partition(32, 2.0, 16.0, 8.0, 4)
assert sum(optimal_layers) == 32
assert optimal_layers[0] < optimal_layers[1]
assert optimal_layers[3] < optimal_layers[2]

balanced_latencies = [
    16.0 + optimal_layers[0] * 2.0,
    optimal_layers[1] * 2.0,
    optimal_layers[2] * 2.0,
    8.0 + optimal_layers[3] * 2.0,
]
_, new_bubble_ratio = scheduler.simulate_1f1b_execution(balanced_latencies, m)
assert new_bubble_ratio < bubble_ratio

print("参考实现验证 100% 通过！")
```
