核心概念

1. GPU 组织（教材 primer）

  • 计算：GPU = 若干 SM（H100：132 个），每个 SM 有 128 个 core。线程以 warp（32 线程） 为单位锁步执行；warp 组成 block（如 512/1024 线程）分配给 SM。
  • 内存层级：寄存器（线程私有）→ 共享内存 + L1（SM 内共享）→ L2（全芯片共享）→ 全局内存 HBM（最大但最慢）。
  • 关键事实：HBM 带宽远低于 SRAM 级别的共享内存/寄存器。很多 kernel 是 memory-bound 而非 compute-bound。

2. 三个经典优化

  • Memory coalescing（访存合并）：DRAM 按突发（burst）返回连续地址。若 warp 内 32 个线程访问连续地址，硬件合并成一次大请求。教材的 naive matmul 例子：线程 (x,y) 映射错位导致 A 的访存不连续，吞吐差 ~10 倍；改 1D block 映射（threadIdx 相邻 → y 相邻）后恢复连续访问。
  • Tiling（分块）：把 A、B 的 tile 先搬进共享内存，块内线程复用，减少对 HBM 的重复访问。教材例子：吞吐 410 GB/s、时间 -43%、~6.6 TFLOPS。
  • Thread coarsening（线程粗化）：每个线程算多个输出元素，减少共享内存指令压力（ncu 里表现为 MIO throttle 停顿）。
  • 控制分歧：warp 内 if 分支导致串行化；用 predication 或重排数据避免。

3. 工具谱系

  • PyTorch：易用、慢。
  • @torch.compile：易用、快、不灵活；TORCH_LOGS=output_code 可以导出生成的 Triton kernel 作为起点。
  • Triton：较快、更灵活（block 级编程，tl.program_id、tl.arange、mask 处理）。
  • CUDA：最快最灵活（共享内存、SM 内调度全部可控），但开发成本最高。

4. Fused kernel

相邻的逐点运算（如 LayerNorm 的多个步骤）若分多个 kernel，中间结果要写回 HBM 再读回。融合成一个 kernel，数据留在 SM 内 → 大幅减少 HBM 往返。FlashAttention 是”融合 + 分块 + online softmax”的集大成者。

5. FlashAttention

朴素注意力的问题：物化 S = QKᵀ（n×n）和 P = softmax(S) 到 HBM，长序列时是最大的激活之一（呼应第 2 课公式中的二次项），且 HBM 带宽成为瓶颈。

FlashAttention 的做法：

  • 把 Q、K、V 分块，每次只算一块 S_ij（SRAM 内）；
  • 用 online softmax：维护 running max m 与 running sum l，每块到来时重新归一化已算的输出 O；
  • 不物化 S、P；显存从 O(n²) 降到 O(n)；计算量不变但访存量大幅下降。

FA-2：减少非 matmul 操作数、按 warp 精细划分工作量；FA-3：面向 Hopper 的 FP8/Tensor Core 优化。限制：只支持特定注意力模式 → FlexAttention。

具体演示

n=4096 的注意力：S 矩阵 4096×4096×2B ≈ 32 MB/层/头——逐层累积后是激活的最大贡献者。FlashAttention 把这块内存需求变成 O(n)，且因为少访存，实际更快。第 8 课的 Ring Attention 用同一套 online softmax 统计量做跨卡分块。

import numpy as np


def standard_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray):
    """参照实现：物化 S 和 P。Q,K,V: (n, d)。"""
    n = Q.shape[0]
    S = Q @ K.T                    # (n, n) —— 长序列下这是内存炸弹
    S = S - S.max(axis=-1, keepdims=True)
    P = np.exp(S)
    P /= P.sum(axis=-1, keepdims=True)
    return P @ V, S


def flash_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray,
                    block_size: int = 64) -> np.ndarray:
    """
    分块实现：不物化完整 S。
    对每个 query 块，逐步处理 kv 块，维护每个 query 行的：
      m: 见过的分数的 running max
      l: 见过的 exp(score - m) 之和（softmax 分母）
      O: 已累加的加权输出
    """
    n, d = Q.shape
    O = np.zeros((n, d))
    l = np.zeros(n)                       # 分母（running sum）
    m = np.full(n, -np.inf)               # running max

    for i in range(0, n, block_size):
        Qi = Q[i:i + block_size]
        Oi = O[i:i + block_size]
        li = l[i:i + block_size]
        mi = m[i:i + block_size]

        for j in range(0, n, block_size):

            Vj = V[j:j + block_size]

            S_ij = Qi @ Kj.T              # 当前块分数 (bs, bs)

            # 2) 旧分母/旧输出都要按 exp(mi - m_new) 缩放，新块贡献 p_ij
            scale = ______
            p_ij = np.exp(S_ij - m_new[:, None])   # 新块的"原始"权重
            l_new = ______                         # 分母更新：旧项缩放 + 新块和
            # 3) 输出更新：旧输出按比例缩放，加上新块贡献

            mi, li = m_new, l_new

        # 把块的统计量写回全局数组

        l[i:i + block_size] = li
        m[i:i + block_size] = mi

    return O / l[:, None]

import numpy as np


def standard_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray):
    """参照实现：物化 S 和 P。Q,K,V: (n, d)。"""
    n = Q.shape[0]
    S = Q @ K.T                    # (n, n) —— 长序列下这是内存炸弹
    S = S - S.max(axis=-1, keepdims=True)
    P = np.exp(S)
    P /= P.sum(axis=-1, keepdims=True)
    return P @ V, S


def flash_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray,
                    block_size: int = 64) -> np.ndarray:
    """
    分块实现：不物化完整 S。
    对每个 query 块，逐步处理 kv 块，维护每个 query 行的：
      m: 见过的分数的 running max
      l: 见过的 exp(score - m) 之和（softmax 分母）
      O: 已累加的加权输出
    """
    n, d = Q.shape
    O = np.zeros((n, d))
    l = np.zeros(n)                       # 分母（running sum）
    m = np.full(n, -np.inf)               # running max

    for i in range(0, n, block_size):
        Qi = Q[i:i + block_size]
        Oi = O[i:i + block_size]
        li = l[i:i + block_size]
        mi = m[i:i + block_size]

        for j in range(0, n, block_size):
            Kj = K[j:j + block_size]
            Vj = V[j:j + block_size]

            S_ij = Qi @ Kj.T              # 当前块分数 (bs, bs)

            # online softmax 更新：
            # 1) 新 running max（把当前块的最大分数并进来）
            m_new = np.maximum(mi, S_ij.max(axis=-1))
            # 2) 旧分母/旧输出都要按 exp(mi - m_new) 缩放，新块贡献 p_ij
            scale = np.exp(mi - m_new)
            p_ij = np.exp(S_ij - m_new[:, None])   # 新块的"原始"权重
            l_new = li * scale + p_ij.sum(axis=-1)                         # 分母更新：旧项缩放 + 新块和
            # 3) 输出更新：旧输出按比例缩放，加上新块贡献
            Oi = Oi * scale[:, None] + p_ij @ Vj
            mi, li = m_new, l_new

        # 把块的统计量写回全局数组
        O[i:i + block_size] = Oi
        l[i:i + block_size] = li
        m[i:i + block_size] = mi

    # 最终归一化：O / l（把 running max 移回）
    return O / l[:, None]

三个问答题要点

Q1

  • 慢：S 与 P 都是 n×n，计算它们要写回 HBM 再读回（每步都要走 HBM 带宽）；n 大时访存时间远超计算（memory-bound）；
  • 占内存：S 是 O(n²)，正是第 2 课激活公式中 5·n_heads·seq²·bs 项——长序列时是激活最大头，全量重计算也救不了（层边界激活仍随 seq 线性增长，但注意力分数矩阵是二次项）；
  • FA 省掉：不物化 S/P（O(n²) → O(n) 内存）；访存量从 O(n²) 次 HBM 读写降到 O(n) 块级读写（每块只进出 SRAM 一次）——计算量不变，但 memory-bound 瓶颈被移除。

Q2

  • naive matmul：线程 (x,y) 都算一个输出元素时，同 warp 的线程 x 相邻但读的是 A 的不同行（行距 = K）→ 不连续 → 无法合并成 DRAM burst；B 的列访问同理；
  • 一维 block 映射（x = blockIdx·BLOCK + threadIdx/BLOCKSIZE，y = threadIdx%BLOCKSIZE）：warp 内相邻线程的 y 相邻 → 读 B 的连续列（行主序下连续）→ 合并；吞吐提升 ~10 倍；
  • Tiling：把 A/B 的 tile 先搬进共享内存，块内所有线程复用 → HBM 访问从”每个线程各读一遍”变成”每 tile 读一次”；
  • Thread coarsening：每个线程算多个输出 → 共享内存指令数减少 → 缓解 MIO 指令队列阻塞（ncu 的 mio_throttle 停顿）。

Q3

  • 谱系：torch.compile（易用/快/不灵活，可导出 Triton 代码作起点）→ Triton（block 级、较快、较灵活）→ CUDA（最难、最快、完全可控）；
  • 必须写 CUDA 的场景：需要精细控制共享内存布局、SM 内调度/warp 划分、特殊指令（如 FA-2/FA-3 的 warp 分工与 FP8 Tensor Core 路径），Triton 只暴露 block 级抽象；
  • FA-1→2→3：FA-1 确立分块 + online softmax + 融合（内存 O(n)）；FA-2 减少非 matmul 操作、按 warp 精细划分 Q/K/V 工作量（提高利用率）；FA-3 面向 Hopper 优化 FP8/Tensor Core 与异步流水线。

通过要点

  • FlashAttention 不降低 FLOPs，降低的是 HBM 访存与显存（O(n²)→O(n)）；
  • online softmax 的 running max 是为了数值稳定（防止 exp 溢出），running sum 是为了正确归一化；
  • 与第 8 课 Ring Attention 共享同一套 online softmax 思想。

### 2. 三个经典优化

- **Memory coalescing（访存合并）**：DRAM 按突发（burst）返回连续地址。若 warp 内 32 个线程访问连续地址，硬件合并成一次大请求。教材的 naive matmul 例子：线程 (x,y) 映射错位导致 A 的访存不连续，吞吐差 ~10 倍；改 1D block 映射（threadIdx 相邻 → y 相邻）后恢复连续访问。
- **Tiling（分块）**：把 A、B 的 tile 先搬进共享内存，块内线程复用，减少对 HBM 的重复访问。教材例子：吞吐 410 GB/s、时间 -43%、~6.6 TFLOPS。
- **Thread coarsening（线程粗化）**：每个线程算多个输出元素，减少共享内存指令压力（ncu 里表现为 MIO throttle 停顿）。
- **控制分歧**：warp 内 if 分支导致串行化；用 predication 或重排数据避免。

### 3. 工具谱系

- **PyTorch**：易用、慢。
- **@torch.compile**：易用、快、不灵活；`TORCH_LOGS=output_code` 可以导出生成的 Triton kernel 作为起点。
- **Triton**：较快、更灵活（block 级编程，`tl.program_id`、`tl.arange`、mask 处理）。
- **CUDA**：最快最灵活（共享内存、SM 内调度全部可控），但开发成本最高。

### 4. Fused kernel

相邻的逐点运算（如 LayerNorm 的多个步骤）若分多个 kernel，中间结果要写回 HBM 再读回。融合成一个 kernel，数据留在 SM 内 → 大幅减少 HBM 往返。FlashAttention 是"融合 + 分块 + online softmax"的集大成者。

### 5. FlashAttention

朴素注意力的问题：物化 S = QKᵀ（n×n）和 P = softmax(S) 到 HBM，长序列时是最大的激活之一（呼应第 2 课公式中的二次项），且 HBM 带宽成为瓶颈。

FlashAttention 的做法：

- 把 Q、K、V 分块，每次只算一块 S_ij（SRAM 内）；
- 用 **online softmax**：维护 running max m 与 running sum l，每块到来时重新归一化已算的输出 O；
- 不物化 S、P；显存从 O(n²) 降到 O(n)；计算量不变但访存量大幅下降。

FA-2：减少非 matmul 操作数、按 warp 精细划分工作量；FA-3：面向 Hopper 的 FP8/Tensor Core 优化。限制：只支持特定注意力模式 → FlexAttention。

## 具体演示

n=4096 的注意力：S 矩阵 4096×4096×2B ≈ 32 MB/层/头——逐层累积后是激活的最大贡献者。FlashAttention 把这块内存需求变成 O(n)，且因为少访存，实际更快。第 8 课的 Ring Attention 用同一套 online softmax 统计量做跨卡分块。

import numpy as np


def standard_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray):
    """参照实现：物化 S 和 P。Q,K,V: (n, d)。"""
    n = Q.shape[0]
    S = Q @ K.T                    # (n, n) —— 长序列下这是内存炸弹

    P = np.exp(S)
    P /= P.sum(axis=-1, keepdims=True)
    return P @ V, S


def flash_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray,
                    block_size: int = 64) -> np.ndarray:
    """
    分块实现：不物化完整 S。
    对每个 query 块，逐步处理 kv 块，维护每个 query 行的：
      m: 见过的分数的 running max
      l: 见过的 exp(score - m) 之和（softmax 分母）
      O: 已累加的加权输出
    """
    n, d = Q.shape
    O = np.zeros((n, d))
    l = np.zeros(n)                       # 分母（running sum）
    m = np.full(n, -np.inf)               # running max

    for i in range(0, n, block_size):
        Qi = Q[i:i + block_size]
        Oi = O[i:i + block_size]
        li = l[i:i + block_size]
        mi = m[i:i + block_size]

        for j in range(0, n, block_size):
            Kj = K[j:j + block_size]
            Vj = V[j:j + block_size]

            S_ij = Qi @ Kj.T              # 当前块分数 (bs, bs)

            # online softmax 更新：
            # 1) 新 running max（把当前块的最大分数并进来）
            m_new = np.maximum(mi, S_ij.max(axis=-1))
            # 2) 旧分母/旧输出都要按 exp(mi - m_new) 缩放，新块贡献 p_ij
            scale = np.exp(mi - m_new)
            p_ij = np.exp(S_ij - m_new[:, None])   # 新块的"原始"权重
            l_new = li * scale + p_ij.sum(axis=-1)                         # 分母更新：旧项缩放 + 新块和
            # 3) 输出更新：旧输出按比例缩放，加上新块贡献
            Oi = Oi * scale[:, None] + p_ij @ Vj
            mi, li = m_new, l_new

        # 把块的统计量写回全局数组
        O[i:i + block_size] = Oi
        l[i:i + block_size] = li
        m[i:i + block_size] = mi

    # 最终归一化：O / l（把 running max 移回）
    return O / l[:, None]

## 三个问答题要点

### Q1

- 慢：S 与 P 都是 n×n，计算它们要写回 HBM 再读回（每步都要走 HBM 带宽）；n 大时访存时间远超计算（memory-bound）；
- 占内存：S 是 O(n²)，正是第 2 课激活公式中 `5·n_heads·seq²·bs` 项——长序列时是激活最大头，全量重计算也救不了（层边界激活仍随 seq 线性增长，但注意力分数矩阵是二次项）；
- FA 省掉：不物化 S/P（O(n²) → O(n) 内存）；访存量从 O(n²) 次 HBM 读写降到 O(n) 块级读写（每块只进出 SRAM 一次）——计算量不变，但 memory-bound 瓶颈被移除。

### Q2

- naive matmul：线程 (x,y) 都算一个输出元素时，同 warp 的线程 x 相邻但读的是 A 的不同行（行距 = K）→ 不连续 → 无法合并成 DRAM burst；B 的列访问同理；
- 一维 block 映射（x = blockIdx·BLOCK + threadIdx/BLOCKSIZE，y = threadIdx%BLOCKSIZE）：warp 内相邻线程的 y 相邻 → 读 B 的连续列（行主序下连续）→ 合并；吞吐提升 ~10 倍；
- Tiling：把 A/B 的 tile 先搬进共享内存，块内所有线程复用 → HBM 访问从"每个线程各读一遍"变成"每 tile 读一次"；
- Thread coarsening：每个线程算多个输出 → 共享内存指令数减少 → 缓解 MIO 指令队列阻塞（ncu 的 mio_throttle 停顿）。

### Q3

- 谱系：torch.compile（易用/快/不灵活，可导出 Triton 代码作起点）→ Triton（block 级、较快、较灵活）→ CUDA（最难、最快、完全可控）；
- 必须写 CUDA 的场景：需要精细控制共享内存布局、SM 内调度/warp 划分、特殊指令（如 FA-2/FA-3 的 warp 分工与 FP8 Tensor Core 路径），Triton 只暴露 block 级抽象；
- FA-1→2→3：FA-1 确立分块 + online softmax + 融合（内存 O(n)）；FA-2 减少非 matmul 操作、按 warp 精细划分 Q/K/V 工作量（提高利用率）；FA-3 面向 Hopper 优化 FP8/Tensor Core 与异步流水线。

## 通过要点

- FlashAttention 不降低 FLOPs，降低的是 HBM 访存与显存（O(n²)→O(n)）；
- online softmax 的 running max 是为了数值稳定（防止 exp 溢出），running sum 是为了正确归一化；
- 与第 8 课 Ring Attention 共享同一套 online softmax 思想。
