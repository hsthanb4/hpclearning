核心概念

1. GPU 硬件微架构层次与存储金字塔（Memory Hierarchy）

要写出达到硬件峰值利用率的深度学习内核，必须深入理解现代 GPU 的物理组织。以 NVIDIA Hopper（H100）架构为例：

  • 计算拓扑（SM / Warp / Thread）：
    • 一张 GPU 芯片由若干个流式多处理器（Streaming Multiprocessor, SM）构成（H100 SXM 配备 132 个 SM）。
    • 每个 SM 包含若干个调度器与执行单元（如 Tensor Core、FP32/FP64 CUDA Core、SFU 特殊函数单元）。
    • 硬件执行的最基本不可分割调度单位是 Warp（线程束，固定为 32 个线程），Warp 内部 32 个线程严格以单指令多线程（SIMT）步调锁步执行。若干个 Warp 组织为逻辑上的 Thread Block（线程块，如 128~1024 线程），调度驻留在一个 SM 上。
  • 物理存储金字塔（带宽与延迟的极端鸿沟）：
    1. 寄存器堆（Registers）：单 SM 容量约 256 KB，全芯片总带宽高达 ≈30∼40 TB/s\approx 30 \sim 40\text{ TB/s}，0~1 个时钟周期延迟，由线程独占；
    2. 共享内存 / L1 缓存（Shared Memory / L1 Cache, SRAM）：单 SM 容量约 228 KB，物理带宽高达 ≈15∼20 TB/s\approx 15 \sim 20\text{ TB/s}，约 20 周期延迟，供同一个 Block 内的所有线程高速协同共享；
    3. L2 缓存（L2 Cache）：全芯片共享（H100 为 50 MB），带宽 ≈5∼8 TB/s\approx 5 \sim 8\text{ TB/s}，约 100~200 周期延迟；
    4. 高带宽全局显存（High Bandwidth Memory, HBM3）：容量 80GB，虽然标称带宽高达 3.35 TB/s3.35\text{ TB/s}，但其访问延迟高达 400∼800400 \sim 800 个时钟周期

内存墙第一性原理： H100 的 Tensor Core 标称计算峰值高达近 1000 TFLOPS1000\text{ TFLOPS}，但外部 HBM 带宽仅为 3.35 TB/s3.35\text{ TB/s}。若一个算子每加载 1 字节数据只做 1 次运算（算术强度极低），硬件必然陷入访存受限（Memory-Bound），绝大部分 SM 将长期处于等待内存数据回包的饥饿停顿状态。

2. 经典 GPU 内核优化四大铁律

高效算子开发的核心目标，是竭尽一切可能将数据截留在高速片上缓存（Registers 与 SRAM）中反复复用，消灭对低速 HBM 的往返读写：

  1. 访存合并（Memory Coalescing）：
    • GPU 全局内存控制器以固定突发（Burst，通常为 32 或 128 字节对齐的缓存行 Cache Line）为单位进行事务传输。
    • 当一个 Warp 内的 32 个线程并发访问连续且对齐的内存地址时，硬件能够将这 32 个内存请求合并为单次 128 字节的物理传输事务，总线利用率达到 100%。
    • 若线程访问地址产生跨度（Strided）或随机离散访问，硬件将被迫发射多达 32 次独立的孤立内存请求，导致总线利用率跌破 10%，引发近十倍的吞吐断崖。
  2. 分块与共享内存复用（Tiling & Shared Memory Staging）：
    • 在矩阵乘法（GEMM）中，利用分块算法将大矩阵拆解为适应 SRAM 容量的子块（Tile）。
    • 将输入 Tile 从 HBM 协同搬运到 Shared Memory 后，块内各个线程反复读取该 Tile 进行乘累加，使 HBM 访存次数降低 BlockSize\text{BlockSize} 倍。
  3. 线程粗化与寄存器分块（Thread Coarsening & Register Tiling）：
    • 让每个 CUDA 线程不再仅负责计算 1 个输出元素，而是负责计算一个微型子块（例如 4×44 \times 4 或 8×88 \times 8 个输出）。
    • 累加过程中的中间变量全程保存在线程私有寄存器中，消除对 Shared Memory 的读写冲突（Bank Conflicts）与指令发射瓶颈。
  4. 消除分支分歧（Warp Divergence Elimination）：
    • 避免在 Warp 内部编写基于线程号的条件分支（if (threadIdx.x % 2 == 0)）。
    • 一旦同一 Warp 内线程执行路径分叉，硬件只能串行执行所有分支路径并用掩码屏蔽无效线程，导致算力有效利用率腰斩。

4. 算子融合（Operator Fusion）与 FlashAttention 的划时代变革

传统的 Attention 机制在数学上定义为： Attention(Q,K,V)=Softmax(QKTd)V\text{Attention}(Q, K, V) = \text{Softmax}\left(\frac{Q K^T}{\sqrt{d}}\right) V

在原生 PyTorch 实现中，该公式被拆解为三个分离的物理内核：

  1. GEMM 1：从 HBM 加载 QQ 与 KK，计算注意力点积分数 S=QKTS = Q K^T，将庞大的 N×NN \times N 矩阵完整写入 HBM（O(N2)O(N^2) 显存）；

  2. Softmax：从 HBM 重新完整读出 SS，计算归一化权重矩阵 P=Softmax(S)P = \text{Softmax}(S)，再次将 N×NN \times N 矩阵完整写回 HBM；

  3. GEMM 2：从 HBM 重新读出 PP 与 VV，计算上下文输出 O=PVO = P V，最终写回 HBM。

  • 痛点曝光：长序列下 N×NN \times N 矩阵极其庞大（例如 N=16kN=16\text{k} 时，单头浮点数高达 2.56 亿个）。整个过程对极其缓慢的 HBM 进行了多达 3 次往返读写。计算时间完全被 HBM 访存延迟统治。

B. FlashAttention 的破局机制（SRAM 瓦片融合 + Online Softmax）

Dao et al. 提出的 FlashAttention 颠覆了上述流程（如图 13-2 所示）：

高带宽显存 (HBM)
片上共享内存 (SRAM)
Tensor Core 计算核心
1分块加载 Q_i 瓦片 (驻留外层循环)
loop内层循环遍历 K, V 瓦片 (j = 1 to T_c)
2分块加载 K_j, V_j
3计算局部得分 S_ij = Q_i K_j^T
4在线更新局部最大值 m_i 与归一化分母 l_i
5增量累加更新注意力输出 O_i
6将最终归一化结果 O_i 写回全局显存

图 13-2：FlashAttention 前向分块双层循环流水与增量更新流

  • 不物化（No Materialization）：不在 HBM 中生成完整的 N×NN \times N 矩阵。

  • 分块载入 SRAM：将 QQ 划分为行块 Qi∈ℝBr×dQ_i \in \mathbb{R}^{B_r \times d}，将 K,VK, V 划分为列块 Kj,Vj∈ℝBc×dK_j, V_j \in \mathbb{R}^{B_c \times d}。将这些紧凑的小块载入片上共享内存（SRAM）。

  • 增量式 Online Softmax： 在 SRAM 内部计算局部点积分数 Sij=QiKjTS_{ij} = Q_i K_j^T，并实时维护行最大值 mm 与归一化分母 ℓ\ell。 当遍历下一个 K,VK, V 块时，利用代数恒等式，直接将旧输出按指数比值 exp⁡(mold−mnew)\exp(m_{\text{old}} - m_{\text{new}}) 重新缩放，就地累加新块贡献。

  • 计算效益：

    • HBM 访存量从标准实现的 Θ(Nd+N2)\Theta(Nd + N^2) 降为 Θ(N2d2M)\Theta\!\left(\frac{N^2 d^2}{M}\right)（MM 为 SRAM 容量，常见 d2≪Md^2 \ll M，因此远小于前者；仍随 NN 二次增长，并不是 O(N)O(N)）；
    • 除输入输出外的额外显存从 O(N2)O(N^2) 降为 O(N)O(N)（每行只保留 m,ℓm, \ell 统计量）；
    • 浮点计算量（FLOPs）基本不变，但 HBM 往返大幅减少，原论文报告墙钟速度提升约 2×∼4×2\times \sim 4\times。

具体演示与数值推演

以单头注意力计算为例，设输入序列长度 N=4096N = 4096，特征维度 d=128d = 128，采用 BF16 精度（每元素 2 字节）：

  • 传统原生注意力的显存与访存量推演：
    • 中间分数矩阵 SS 尺寸为 4096×40964096 \times 4096，需物化存储： MemoryS=4096×4096×2 字节=33,554,432 字节=32 MiB≈33.6 MB\text{Memory}_{S} = 4096 \times 4096 \times 2\text{ 字节} = 33,554,432\text{ 字节} = 32\text{ MiB} \approx 33.6\text{ MB}
    • 加上 Softmax 权重矩阵 PP（同为 32 MiB32\text{ MiB}），单头单层即产生 64 MiB64\text{ MiB} 的临时中间显存。若网络拥有 32 个注意力头与 32 层深度，全网单样本的注意力中间激活为： Total Memory=32×32×64 MiB=65,536 MiB=64 GiB≈68.7 GB\text{Total Memory} = 32 \times 32 \times 64\text{ MiB} = 65,536\text{ MiB} = 64\text{ GiB} \approx 68.7\text{ GB}
    • 显存直接被中间激活耗尽。同时，读写这批矩阵需要往返吞吐数百 GB 的 HBM 流量。
  • FlashAttention 分块融合推演：
    • 设置 SRAM 分块尺寸 Br=Bc=64B_r = B_c = 64。
    • 单个分块在片上 SRAM 中仅占用： Tile Memory=64×64×2 字节=8192 字节=8 KB\text{Tile Memory} = 64 \times 64 \times 2\text{ 字节} = 8192\text{ 字节} = 8\text{ KB}
    • 8 KB 的小张量可以完全装进每个 SM 的 Shared Memory（容量高达 228 KB）中。
    • 全过程没有 N×NN \times N 中间矩阵写回 HBM，原本 64 GiB64\text{ GiB} 的二次方激活不再需要保存（只保留线性规模的输出 OO 与每行统计量，反向时在片上重算）。这为训练省出几十 GiB 显存，也使注意力层更接近算力受限（Compute Bound）。

代码填空题

用 numpy 实现分块 online softmax 注意力，验证与标准实现数值一致。

Code 
import numpy as np

def standard_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray):
    """参照实现：物化 S 和 P。Q,K,V: (n, d)。"""
    n = Q.shape[0]
    S = Q @ K.T                    # (n, n) —— 长序列下这是内存炸弹
    S = S - S.max(axis=-1, keepdims=True)
    P = np.exp(S)
    P /= P.sum(axis=-1, keepdims=True)
    return P @ V, S

def flash_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray,
                    block_size: int = 64) -> np.ndarray:
    """
    分块实现：不物化完整 S。
    对每个 query 块，逐步处理 kv 块，维护每个 query 行的：
      m: 见过的分数的 running max
      l: 见过的 exp(score - m) 之和（softmax 分母）
      O: 已累加的加权输出
    """
    n, d = Q.shape
    O = np.zeros((n, d))
    l = np.zeros(n)                       # 分母（running sum）
    m = np.full(n, -np.inf)               # running max

    for i in range(0, n, block_size):
        Qi = Q[i:i + block_size]
        Oi = O[i:i + block_size]
        li = l[i:i + block_size]
        mi = m[i:i + block_size]

        for j in range(0, n, block_size):
            Kj = K[j:j + block_size]
            Vj = V[j:j + block_size]

            S_ij = Qi @ Kj.T              # 当前块分数 (bs, bs)

            # online softmax 更新：
            # 1) 新 running max（把当前块的最大分数并进来）
            m_new = ______
            # 2) 旧分母/旧输出都要按 exp(mi - m_new) 缩放，新块贡献 p_ij
            scale = ______
            p_ij = np.exp(S_ij - m_new[:, None])   # 新块的"原始"权重
            l_new = ______                         # 分母更新：旧项缩放 + 新块和
            # 3) 输出更新：旧输出按比例缩放，加上新块贡献
            Oi = ______
            mi, li = m_new, l_new

        # 把块的统计量写回全局数组
        O[i:i + block_size] = Oi
        l[i:i + block_size] = li
        m[i:i + block_size] = mi

    # 最终归一化：O / l（把 running max 移回）
    return O / l[:, None]

if __name__ == "__main__":
    rng = np.random.default_rng(0)
    n, d = 256, 32
    Q = rng.standard_normal((n, d)) * 0.5
    K = rng.standard_normal((n, d)) * 0.5
    V = rng.standard_normal((n, d))

    O_ref, S_ref = standard_attention(Q, K, V)
    O_flash = flash_attention(Q, K, V, block_size=32)

    print("最大绝对误差:", np.abs(O_ref - O_flash).max())
    print("S 矩阵元素数:", S_ref.size, "（FlashAttention 不物化它）")
    assert np.allclose(O_ref, O_flash, atol=1e-6)
    print("与标准注意力一致 ✓（内存从 O(n²) 降到 O(n)）")

import numpy as np

def standard_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray):
    """参照实现：物化 S 和 P。Q,K,V: (n, d)。"""
    n = Q.shape[0]
    S = Q @ K.T                    # (n, n) —— 长序列下这是内存炸弹
    S = S - S.max(axis=-1, keepdims=True)
    P = np.exp(S)
    P /= P.sum(axis=-1, keepdims=True)
    return P @ V, S

def flash_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray,
                    block_size: int = 64) -> np.ndarray:
    """
    分块实现：不物化完整 S。
    对每个 query 块，逐步处理 kv 块，维护每个 query 行的：
      m: 见过的分数的 running max
      l: 见过的 exp(score - m) 之和（softmax 分母）
      O: 已累加的加权输出
    """
    n, d = Q.shape
    O = np.zeros((n, d))
    l = np.zeros(n)                       # 分母（running sum）
    m = np.full(n, -np.inf)               # running max

    for i in range(0, n, block_size):
        Qi = Q[i:i + block_size]
        Oi = O[i:i + block_size]
        li = l[i:i + block_size]
        mi = m[i:i + block_size]

        for j in range(0, n, block_size):
            Kj = K[j:j + block_size]
            Vj = V[j:j + block_size]

            S_ij = Qi @ Kj.T              # 当前块分数 (bs, bs)

            # online softmax 更新：
            # 1) 新 running max（把当前块的最大分数并进来）
            m_new = np.maximum(mi, S_ij.max(axis=-1))
            # 2) 旧分母/旧输出都要按 exp(mi - m_new) 缩放，新块贡献 p_ij
            scale = np.exp(mi - m_new)
            p_ij = np.exp(S_ij - m_new[:, None])   # 新块的"原始"权重
            l_new = li * scale + p_ij.sum(axis=-1)                         # 分母更新：旧项缩放 + 新块和
            # 3) 输出更新：旧输出按比例缩放，加上新块贡献
            Oi = Oi * scale[:, None] + p_ij @ Vj
            mi, li = m_new, l_new

        # 把块的统计量写回全局数组
        O[i:i + block_size] = Oi
        l[i:i + block_size] = li
        m[i:i + block_size] = mi

    # 最终归一化：O / l（把 running max 移回）
    return O / l[:, None]

if __name__ == "__main__":
    rng = np.random.default_rng(0)
    n, d = 256, 32
    Q = rng.standard_normal((n, d)) * 0.5
    K = rng.standard_normal((n, d)) * 0.5
    V = rng.standard_normal((n, d))

    O_ref, S_ref = standard_attention(Q, K, V)
    O_flash = flash_attention(Q, K, V, block_size=32)

    print("最大绝对误差:", np.abs(O_ref - O_flash).max())
    print("S 矩阵元素数:", S_ref.size, "（FlashAttention 不物化它）")
    assert np.allclose(O_ref, O_flash, atol=1e-6)
    print("与标准注意力一致 ✓（内存从 O(n²) 降到 O(n)）")

三个问答题要点

Q1

  • 慢：S 与 P 都是 n×n，计算它们要写回 HBM 再读回（每步都要走 HBM 带宽）；n 大时访存时间远超计算（memory-bound）；
  • 占内存：S 是 O(n²)，正是第 2 课激活公式中 5·n_heads·seq²·bs 项——长序列时是激活最大头，全量重计算也救不了（层边界激活仍随 seq 线性增长，但注意力分数矩阵是二次项）；
  • FA 省掉：不物化 S/P（O(n²) → O(n) 内存）；HBM 访存量从 Θ(nd + n²) 降到 Θ(n²d²/M)（M 为 SRAM 容量），额外显存从 O(n²) 降到 O(n)——计算量不变，但 memory-bound 瓶颈被大幅缓解。

Q2

  • naive matmul：线程 (x,y) 都算一个输出元素时，同 warp 的线程 x 相邻但读的是 A 的不同行（行距 = K）→ 不连续 → 无法合并成 DRAM burst；B 的列访问同理；
  • 一维 block 映射（x = blockIdx·BLOCK + threadIdx/BLOCKSIZE，y = threadIdx%BLOCKSIZE）：warp 内相邻线程的 y 相邻 → 读 B 的连续列（行主序下连续）→ 合并；吞吐提升 ~10 倍；
  • Tiling：把 A/B 的 tile 先搬进共享内存，块内所有线程复用 → HBM 访问从”每个线程各读一遍”变成”每 tile 读一次”；
  • Thread coarsening：每个线程算多个输出 → 共享内存指令数减少 → 缓解 MIO 指令队列阻塞（ncu 的 mio_throttle 停顿）。

Q3

  • 谱系：torch.compile（易用/快/不灵活，可导出 Triton 代码作起点）→ Triton（block 级、较快、较灵活）→ CUDA（最难、最快、完全可控）；
  • 必须写 CUDA 的场景：需要精细控制共享内存布局、SM 内调度/warp 划分、特殊指令（如 FA-2/FA-3 的 warp 分工与 FP8 Tensor Core 路径），Triton 只暴露 block 级抽象；
  • FA-1→2→3：FA-1 确立分块 + online softmax + 融合（内存 O(n)）；FA-2 减少非 matmul 操作、按 warp 精细划分 Q/K/V 工作量（提高利用率）；FA-3 面向 Hopper 优化 FP8/Tensor Core 与异步流水线。

通过要点

  • FlashAttention 不降低 FLOPs，降低的是 HBM 访存（降为 Θ(n²d²/M)）与额外显存（O(n²)→O(n)）；
  • online softmax 的 running max 是为了数值稳定（防止 exp 溢出），running sum 是为了正确归一化；
  • 与第 8 课 Ring Attention 共享同一套 online softmax 思想。

## 核心概念

### 1. GPU 硬件微架构层次与存储金字塔（Memory Hierarchy）

要写出达到硬件峰值利用率的深度学习内核，必须深入理解现代 GPU 的物理组织。以 NVIDIA Hopper（H100）架构为例：

- **计算拓扑（SM / Warp / Thread）**：
   - 一张 GPU 芯片由若干个**流式多处理器（Streaming Multiprocessor, SM）**构成（H100 SXM 配备 132 个 SM）。
   - 每个 SM 包含若干个调度器与执行单元（如 Tensor Core、FP32/FP64 CUDA Core、SFU 特殊函数单元）。
   - 硬件执行的最基本不可分割调度单位是 **Warp（线程束，固定为 32 个线程）**，Warp 内部 32 个线程严格以单指令多线程（SIMT）步调锁步执行。若干个 Warp 组织为逻辑上的 **Thread Block（线程块，如 128~1024 线程）**，调度驻留在一个 SM 上。
- **物理存储金字塔（带宽与延迟的极端鸿沟）**：
  1. **寄存器堆（Registers）**：单 SM 容量约 256 KB，全芯片总带宽高达 $\approx 30 \sim 40\text{ TB/s}$，0~1 个时钟周期延迟，由线程独占；
  2. **共享内存 / L1 缓存（Shared Memory / L1 Cache, SRAM）**：单 SM 容量约 228 KB，物理带宽高达 $\approx 15 \sim 20\text{ TB/s}$，约 20 周期延迟，供同一个 Block 内的所有线程高速协同共享；
  3. **L2 缓存（L2 Cache）**：全芯片共享（H100 为 50 MB），带宽 $\approx 5 \sim 8\text{ TB/s}$，约 100~200 周期延迟；
  4. **高带宽全局显存（High Bandwidth Memory, HBM3）**：容量 80GB，虽然标称带宽高达 $3.35\text{ TB/s}$，但其访问延迟高达 $400 \sim 800$ 个时钟周期

**内存墙第一性原理**：
H100 的 Tensor Core 标称计算峰值高达近 $1000\text{ TFLOPS}$，但外部 HBM 带宽仅为 $3.35\text{ TB/s}$。若一个算子每加载 1 字节数据只做 1 次运算（算术强度极低），硬件必然陷入**访存受限（Memory-Bound）**，绝大部分 SM 将长期处于等待内存数据回包的饥饿停顿状态。

### 2. 经典 GPU 内核优化四大铁律

高效算子开发的核心目标，是竭尽一切可能**将数据截留在高速片上缓存（Registers 与 SRAM）中反复复用，消灭对低速 HBM 的往返读写**：

1. **访存合并（Memory Coalescing）**：
   - GPU 全局内存控制器以固定突发（Burst，通常为 32 或 128 字节对齐的缓存行 Cache Line）为单位进行事务传输。
   - 当一个 Warp 内的 32 个线程并发访问连续且对齐的内存地址时，硬件能够将这 32 个内存请求**合并为单次 128 字节的物理传输事务**，总线利用率达到 100%。
   - 若线程访问地址产生跨度（Strided）或随机离散访问，硬件将被迫发射多达 32 次独立的孤立内存请求，导致总线利用率跌破 10%，引发近十倍的吞吐断崖。

2. **分块与共享内存复用（Tiling & Shared Memory Staging）**：
   - 在矩阵乘法（GEMM）中，利用分块算法将大矩阵拆解为适应 SRAM 容量的子块（Tile）。
   - 将输入 Tile 从 HBM 协同搬运到 Shared Memory 后，块内各个线程反复读取该 Tile 进行乘累加，使 HBM 访存次数降低 $\text{BlockSize}$ 倍。

3. **线程粗化与寄存器分块（Thread Coarsening & Register Tiling）**：
   - 让每个 CUDA 线程不再仅负责计算 1 个输出元素，而是负责计算一个微型子块（例如 $4 \times 4$ 或 $8 \times 8$ 个输出）。
   - 累加过程中的中间变量全程保存在线程私有寄存器中，消除对 Shared Memory 的读写冲突（Bank Conflicts）与指令发射瓶颈。

4. **消除分支分歧（Warp Divergence Elimination）**：
   - 避免在 Warp 内部编写基于线程号的条件分支（`if (threadIdx.x % 2 == 0)`）。
   - 一旦同一 Warp 内线程执行路径分叉，硬件只能串行执行所有分支路径并用掩码屏蔽无效线程，导致算力有效利用率腰斩。

### 4. 算子融合（Operator Fusion）与 FlashAttention 的划时代变革

$$\text{Attention}(Q, K, V) = \text{Softmax}\left(\frac{Q K^T}{\sqrt{d}}\right) V$$

在原生 PyTorch 实现中，该公式被拆解为三个分离的物理内核：

1. **GEMM 1**：从 HBM 加载 $Q$ 与 $K$，计算注意力点积分数 $S = Q K^T$，将庞大的 $N \times N$ 矩阵完整**写入 HBM**（$O(N^2)$ 显存）；

2. **Softmax**：从 HBM 重新完整读出 $S$，计算归一化权重矩阵 $P = \text{Softmax}(S)$，再次将 $N \times N$ 矩阵完整**写回 HBM**；

3. **GEMM 2**：从 HBM 重新读出 $P$ 与 $V$，计算上下文输出 $O = P V$，最终写回 HBM。

- **痛点曝光**：长序列下 $N \times N$ 矩阵极其庞大（例如 $N=16\text{k}$ 时，单头浮点数高达 2.56 亿个）。整个过程对极其缓慢的 HBM 进行了多达 **3 次往返读写**。计算时间完全被 HBM 访存延迟统治。

<p class="caption" align="center"><em>图 13-2：FlashAttention 前向分块双层循环流水与增量更新流</em></p>


- **不物化（No Materialization）**：**不在 HBM 中生成完整的 $N \times N$ 矩阵**。
- **分块载入 SRAM**：将 $Q$ 划分为行块 $Q_i \in \mathbb{R}^{B_r \times d}$，将 $K, V$ 划分为列块 $K_j, V_j \in \mathbb{R}^{B_c \times d}$。将这些紧凑的小块载入片上共享内存（SRAM）。
- **增量式 Online Softmax**：
  在 SRAM 内部计算局部点积分数 $S_{ij} = Q_i K_j^T$，并实时维护行最大值 $m$ 与归一化分母 $\ell$。
  当遍历下一个 $K, V$ 块时，利用代数恒等式，直接将旧输出按指数比值 $\exp(m_{\text{old}} - m_{\text{new}})$ 重新缩放，就地累加新块贡献。

- **计算效益**：
   - HBM 访存量从标准实现的 $\Theta(Nd + N^2)$ 降为 $\Theta\!\left(\frac{N^2 d^2}{M}\right)$（$M$ 为 SRAM 容量，常见 $d^2 \ll M$，因此远小于前者；仍随 $N$ 二次增长，并不是 $O(N)$）；
   - 除输入输出外的额外显存从 $O(N^2)$ 降为 $O(N)$（每行只保留 $m, \ell$ 统计量）；
   - 浮点计算量（FLOPs）基本不变，但 HBM 往返大幅减少，原论文报告墙钟速度提升约 **$2\times \sim 4\times$**。

## 具体演示与数值推演

以单头注意力计算为例，设输入序列长度 $N = 4096$，特征维度 $d = 128$，采用 BF16 精度（每元素 2 字节）：

- **传统原生注意力的显存与访存量推演**：
   - 中间分数矩阵 $S$ 尺寸为 $4096 \times 4096$，需物化存储：
    $$\text{Memory}_{S} = 4096 \times 4096 \times 2\text{ 字节} = 33,554,432\text{ 字节} = 32\text{ MiB} \approx 33.6\text{ MB}$$
   - 加上 Softmax 权重矩阵 $P$（同为 $32\text{ MiB}$），单头单层即产生 $64\text{ MiB}$ 的临时中间显存。若网络拥有 32 个注意力头与 32 层深度，全网单样本的注意力中间激活为：
    $$\text{Total Memory} = 32 \times 32 \times 64\text{ MiB} = 65,536\text{ MiB} = 64\text{ GiB} \approx 68.7\text{ GB}$$
   - 显存直接被中间激活耗尽。同时，读写这批矩阵需要往返吞吐数百 GB 的 HBM 流量。

- **FlashAttention 分块融合推演**：
   - 设置 SRAM 分块尺寸 $B_r = B_c = 64$。
   - 单个分块在片上 SRAM 中仅占用：
    $$\text{Tile Memory} = 64 \times 64 \times 2\text{ 字节} = 8192\text{ 字节} = 8\text{ KB}$$
   - 8 KB 的小张量可以完全装进每个 SM 的 Shared Memory（容量高达 228 KB）中。
   - 全过程没有 $N \times N$ 中间矩阵写回 HBM，原本 $64\text{ GiB}$ 的二次方激活不再需要保存（只保留线性规模的输出 $O$ 与每行统计量，反向时在片上重算）。这为训练省出几十 GiB 显存，也使注意力层更接近算力受限（Compute Bound）。

```{python}
#| course_role: solution
import numpy as np

def standard_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray):
    """参照实现：物化 S 和 P。Q,K,V: (n, d)。"""
    n = Q.shape[0]
    S = Q @ K.T                    # (n, n) —— 长序列下这是内存炸弹
    S = S - S.max(axis=-1, keepdims=True)
    P = np.exp(S)
    P /= P.sum(axis=-1, keepdims=True)
    return P @ V, S

def flash_attention(Q: np.ndarray, K: np.ndarray, V: np.ndarray,
                    block_size: int = 64) -> np.ndarray:
    """
    分块实现：不物化完整 S。
    对每个 query 块，逐步处理 kv 块，维护每个 query 行的：
      m: 见过的分数的 running max
      l: 见过的 exp(score - m) 之和（softmax 分母）
      O: 已累加的加权输出
    """
    n, d = Q.shape
    O = np.zeros((n, d))
    l = np.zeros(n)                       # 分母（running sum）
    m = np.full(n, -np.inf)               # running max

    for i in range(0, n, block_size):
        Qi = Q[i:i + block_size]
        Oi = O[i:i + block_size]
        li = l[i:i + block_size]
        mi = m[i:i + block_size]

        for j in range(0, n, block_size):
            Kj = K[j:j + block_size]
            Vj = V[j:j + block_size]

            S_ij = Qi @ Kj.T              # 当前块分数 (bs, bs)

            # online softmax 更新：
            # 1) 新 running max（把当前块的最大分数并进来）
            m_new = np.maximum(mi, S_ij.max(axis=-1))
            # 2) 旧分母/旧输出都要按 exp(mi - m_new) 缩放，新块贡献 p_ij
            scale = np.exp(mi - m_new)
            p_ij = np.exp(S_ij - m_new[:, None])   # 新块的"原始"权重
            l_new = li * scale + p_ij.sum(axis=-1)                         # 分母更新：旧项缩放 + 新块和
            # 3) 输出更新：旧输出按比例缩放，加上新块贡献
            Oi = Oi * scale[:, None] + p_ij @ Vj
            mi, li = m_new, l_new

        # 把块的统计量写回全局数组
        O[i:i + block_size] = Oi
        l[i:i + block_size] = li
        m[i:i + block_size] = mi

    # 最终归一化：O / l（把 running max 移回）
    return O / l[:, None]

    n, d = 256, 32
```

## 三个问答题要点

### Q1

- 慢：S 与 P 都是 n×n，计算它们要写回 HBM 再读回（每步都要走 HBM 带宽）；n 大时访存时间远超计算（memory-bound）；
- 占内存：S 是 O(n²)，正是第 2 课激活公式中 `5·n_heads·seq²·bs` 项——长序列时是激活最大头，全量重计算也救不了（层边界激活仍随 seq 线性增长，但注意力分数矩阵是二次项）；
- FA 省掉：不物化 S/P（O(n²) → O(n) 内存）；HBM 访存量从 Θ(nd + n²) 降到 Θ(n²d²/M)（M 为 SRAM 容量），额外显存从 O(n²) 降到 O(n)——计算量不变，但 memory-bound 瓶颈被大幅缓解。

### Q2

- naive matmul：线程 (x,y) 都算一个输出元素时，同 warp 的线程 x 相邻但读的是 A 的不同行（行距 = K）→ 不连续 → 无法合并成 DRAM burst；B 的列访问同理；
- 一维 block 映射（x = blockIdx·BLOCK + threadIdx/BLOCKSIZE，y = threadIdx%BLOCKSIZE）：warp 内相邻线程的 y 相邻 → 读 B 的连续列（行主序下连续）→ 合并；吞吐提升 ~10 倍；
- Tiling：把 A/B 的 tile 先搬进共享内存，块内所有线程复用 → HBM 访问从"每个线程各读一遍"变成"每 tile 读一次"；
- Thread coarsening：每个线程算多个输出 → 共享内存指令数减少 → 缓解 MIO 指令队列阻塞（ncu 的 mio_throttle 停顿）。

### Q3

- 谱系：torch.compile（易用/快/不灵活，可导出 Triton 代码作起点）→ Triton（block 级、较快、较灵活）→ CUDA（最难、最快、完全可控）；
- 必须写 CUDA 的场景：需要精细控制共享内存布局、SM 内调度/warp 划分、特殊指令（如 FA-2/FA-3 的 warp 分工与 FP8 Tensor Core 路径），Triton 只暴露 block 级抽象；
- FA-1→2→3：FA-1 确立分块 + online softmax + 融合（内存 O(n)）；FA-2 减少非 matmul 操作、按 warp 精细划分 Q/K/V 工作量（提高利用率）；FA-3 面向 Hopper 优化 FP8/Tensor Core 与异步流水线。

## 通过要点

- FlashAttention 不降低 FLOPs，降低的是 HBM 访存（降为 Θ(n²d²/M)）与额外显存（O(n²)→O(n)）；
- online softmax 的 running max 是为了数值稳定（防止 exp 溢出），running sum 是为了正确归一化；
- 与第 8 课 Ring Attention 共享同一套 online softmax 思想。
