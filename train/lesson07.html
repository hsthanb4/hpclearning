1. 术语澄清：Megatron-SP 与 Context Parallelism (CP) 的本质区别

在大模型分布式系统领域，“序列并行（Sequence Parallelism）”这个词在历史上有两种完全不同的含义，面试与系统设计中极易混淆： 1. Megatron-SP（Korthikanti et al., 2022，本课核心）：专指与机内张量并行（TP）深度绑定的优化技术。它并不改变注意力机制的计算拓扑，而是专门针对 Transformer 中未被 TP 覆盖的区域（如 LayerNorm、RMSNorm、Dropout、残差连接等），通过沿序列维度（Sequence Dimension）切分来彻底消除其显存冗余。 2. Context Parallelism（CP / 环形注意力 Ring-Attention，第 8 课）：专指跨物理节点将全模型的长文本序列（如 32k、128k、1M 上下文）整体切分并分布式流转计算的独立并行维度。

在讨论序列并行时，必须首先明确其上下文语境。

2. 传统 TP 的显存软肋：非 TP 区域的激活冗余

回顾第 6 课，张量并行（TP）成功将 MLP 和 Attention 核心的 GEMM 权重切分到各个 GPU 上，其内部中间激活张量的隐藏维度也被切分为 \(\frac{h}{\text{TP}}\)。

然而，如图 7-1 的对比所示，在 GEMM 算子之外的非 TP 区域，系统面临严峻的显存回弹： - LayerNorm / RMSNorm 的归一化计算： \[\mu = \frac{1}{h} \sum_{i=1}^h x_i, \quad \sigma^2 = \frac{1}{h} \sum_{i=1}^h (x_i - \mu)^2, \quad \text{LayerNorm}(x) = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} \odot \gamma + \beta\] 均值 \(\mu\) 与方差 \(\sigma^2\) 是沿着整个隐藏特征维度 \(h\) 进行统计约简的。若沿 \(h\) 维度切分输入，各卡仅持有一部分通道特征，根本无法独立计算出正确的均值和方差，除非在 LayerNorm 内部强行插入跨卡通信。 - 全量激活冗余驻留：为了避免在每个 Norm 算子内发生低效的跨卡通信，原生 Megatron-LM 规定：在进入 LayerNorm、Dropout 以及残差连接之前，必须持有全量的特征张量 \((b, s, h)\)。 - 后果：这意味着每个 TP 副本的 GPU 显存内都完整保存了一份完全相同的 \((b, s, h)\) 激活张量。随着模型层数 \(L\) 与上下文长度 \(s\) 的增长，这些未被切分的“公共激活值”占据了反向保留激活（Stored Activations）总量的 30%~50%，严重抵消了 TP 带来的显存收益。

3. 序列切分与通信共轭对（\(f/f^*\) 与 \(g/g^*\) 原语闭环）

Megatron-SP 捕捉到了一个核心数学事实：LayerNorm、RMSNorm、GELU 和 Dropout 均是逐 Token（Token-wise）独立执行的算子！ 它们在序列维度 \(s\) 上没有任何交叉依赖——第 1 个 Token 的归一化结果与第 100 个 Token 的归一化完全互不影响。

因此，完全可以沿序列维度 \(s\) 将非 TP 区域的张量均分为 \(\frac{s}{\text{TP}}\) 块，让每张卡仅驻留 \((b, \frac{s}{\text{TP}}, h)\) 的局部序列激活！

为了在 SP 区域（序列切分）与 TP 区域（隐藏维切分）之间无缝转换，Megatron 引入了优雅的共轭算子对（Conjugate Operator Pairs），其执行拓扑如图 7-2 所示：

A. \(g\) 与 \(g^*\) 算子对（SP 与 TP 区域的转换核心）

  • 前向转入 TP 区域（\(g\) 算子）：
    • 在进入 Attention / MLP 的列并行矩阵乘之前，算子需要完整的 Token 语义（例如 Attention QKV 投影需与整体位置编码配合）。
    • 系统发起一次 All-Gather(沿序列维度 \(s\))： \[(b, \frac{s}{\text{TP}}, h) \xrightarrow{g = \text{All-Gather}(s)} (b, s, h)\]
    • 随后直接送入列并行线性层，输出沿隐藏维切分的张量 \((b, s, \frac{h}{\text{TP}})\)。
  • 前向转出 TP 区域（\(g^*\) 算子）：
    • 行并行线性层计算后，各卡产生了部分和张量 \((b, s, h)\)。
    • 在原生 TP 中，此处必须执行一次 AllReduce 沿 \(h\) 恢复完整和。
    • 而在 SP 中，此处直接替换为 Reduce-Scatter(沿序列维度 \(s\))： \[(b, s, \frac{h}{\text{TP}}) \xrightarrow{\text{Row Linear}} (b, s, h) \xrightarrow{g^* = \text{Reduce-Scatter}(s)} (b, \frac{s}{\text{TP}}, h)\]
    • 一石二鸟：Reduce-Scatter 既完成了行并行部分和的累加求和，又顺手将输出张量切分回了 \((b, \frac{s}{\text{TP}}, h)\)，直接喂给后续的 LayerNorm 与 Dropout！

B. 共轭算子的反向行为与对偶性

在自动微分（Autograd）中，反向求导是前向有向无环图的伴随转置： - 前向执行 \(g\)（All-Gather 沿 \(s\)），反向求导对应的梯度汇聚算子正是其转置对偶：Reduce-Scatter 沿 \(s\)。 - 前向执行 \(g^*\)（Reduce-Scatter 沿 \(s\)），反向求导对应的梯度恢复算子正是其转置对偶：All-Gather 沿 \(s\)。 - 这种代数上的高度自洽保证了前向与反向在数学上严格等价，完全无须破坏自动求导链条。

4. 通信量守恒定理：为什么 SP 几乎是“免费的午餐”？

直觉上，引入更多的通信算子会导致通信耗时增加。但严格的集合通信带宽分析证明：Megatron-SP 没有增加任何网络传输字节量！

回顾第 3 课的核心结论：在 Ring 环形通信算法下，一次 AllReduce 在底层完全等价于一次 Reduce-Scatter 紧接一次 All-Gather： \[\text{AllReduce}(X) \equiv \text{All-Gather}(\text{Reduce-Scatter}(X))\] 其单步通信字节数关系为： \[V_{\text{AllReduce}} = 2 \times \frac{\text{TP} - 1}{\text{TP}} \times \text{Size}, \quad V_{\text{Reduce-Scatter}} = V_{\text{All-Gather}} = \frac{\text{TP} - 1}{\text{TP}} \times \text{Size}\]

  • 纯 TP 模式每 Block 通信量： 前向包含 2 次 AllReduce（Attention 输出 + MLP 输出）： \[V_{\text{TP}} = 2 \times V_{\text{AllReduce}} = 4 \times \frac{\text{TP}-1}{\text{TP}} \times (b \cdot s \cdot h \cdot 2)\]

  • TP + SP 模式每 Block 通信量： 前向包含 2 次 All-Gather（进入 Col Linear）+ 2 次 Reduce-Scatter（退出 Row Linear）： \[V_{\text{TP+SP}} = 2 \times (V_{\text{All-Gather}} + V_{\text{Reduce-Scatter}}) = 4 \times \frac{\text{TP}-1}{\text{TP}} \times (b \cdot s \cdot h \cdot 2)\]

  • 重要结论：\(V_{\text{TP+SP}} \equiv V_{\text{TP}}\)！两者的通信总量完全相等。

    • 虽然网络操作次数翻倍（从 2 次大包变成 4 次半包），但通信数据量被严格均摊。
    • 在机内高速 NVLink 环境下，多出发射两次小集合通信的延迟开销（约 \(2\mu s\)）微乎其微。
    • 作为回报，模型所有非 TP 区域的驻留激活显存被直接消减了 \(\text{TP}\) 倍（例如 8 卡下直接砍掉 87.5% 激活显存）。

具体演示与数值推演

以一个 70B 模型（隐藏层维度 \(h=8192\)，层数 \(L=80\)），在 \(\text{TP}=8\)、序列长度 \(s=16384\)（16k 上下文）、单卡批次 \(\text{MBS}=1\)（BF16 精度，每元素 2 字节）下的单层驻留激活为例：

  • 未开启 SP（原生 TP-only）： 每个 Block 内的 LayerNorm 与 Dropout 输入张量必须完整物化，单层静态驻留激活为： \[M_{\text{act/layer}} \approx 1 \times 16384 \times 8192 \times 2\text{ 字节} \approx 268.4\text{ MB}\] 全网 80 层累加的静态常驻激活高达： \[M_{\text{total\_act}} \approx 80 \times 268.4\text{ MB} \approx 21.5\text{ GB}\] 在 80GB 显卡上，仅这部分未切分的冗余激活就吃掉了超过四分之一的宝贵显存空间。

  • 开启 SP（TP + SP 协同）： LayerNorm 与 Dropout 的输入切为 \((1, \frac{16384}{8}, 8192) = (1, 2048, 8192)\)，单层驻留激活降为： \[M_{\text{act/layer\_SP}} \approx 1 \times 2048 \times 8192 \times 2\text{ 字节} \approx 33.55\text{ MB} \quad (\text{仅为原来的 } 1/8)\] 80 层累计驻留激活仅需约 \(2.68\text{ GB}\)！直接省出近 \(19\text{ GB}\) 显存，足以容纳更长的上下文或成倍增加训练 Batch Size。

def trace_block(
    seq: int, hidden: int, tp: int, enable_sp: bool, batch: int = 1,
) -> list[tuple[str, int, int]]:
    """
    返回 [(区域名, s, h)]：前向经过 block 时激活形状的轨迹（每 token 两字节 BF16 可算字节数）。

    算子表（对 (s, h) 的作用）：
      split_seq    : s -> s/tp      （SP 区入口 / g* 出口）
      gather_seq   : s -> s*tp      （g：SP -> TP）
      split_hidden : h -> h/tp      （col-linear 切 h）
      gather_hidden: h -> h*tp      （row-linear 恢复 h）

      layernorm → col_linear → gelu → row_linear → dropout

    def split_hidden(s, h): return (s, h // tp)

    def noop(s, h): return (s, h)

        # 反向真正需要的是它的输入（上一区域的 (s, h/tp)）——所以标记为不驻留。
        persists = not (enable_sp and name == "row_linear")
        trace.append((name, s, h, persists))                    # 驻留激活（要存给反向）
        if enable_sp and name == "row_linear":

            s, h = split_seq(s, h)
            trace.append(("g* (reduce-scatter seq)", s, h, False))
    return trace

        "dropout": noop,
    }
    plan = sp_ops if enable_sp else region_ops

    s, h = seq, hidden
    trace = []
    for name, op in plan.items():
        if enable_sp and name == "col_linear":
            # SP -> TP 过渡：g = all-gather 沿序列维，恢复完整 s
            s, h = gather_seq(s, h)
            trace.append(("g (all-gather seq)", s, h, False))   # 瞬态通信缓冲
        s, h = op(s, h)
        # SP 模式下 row-linear 的 (s, h) 输出是瞬态（随后被 g* 切回序列分片），
        # 反向真正需要的是它的输入（上一区域的 (s, h/tp)）——所以标记为不驻留。
        persists = not (enable_sp and name == "row_linear")
        trace.append((name, s, h, persists))                    # 驻留激活（要存给反向）
        if enable_sp and name == "row_linear":
            trace.append(("row_out (full h)", s, h, False))      # 瞬态：随后被 g* 切回
            s, h = split_seq(s, h)
            trace.append(("g* (reduce-scatter seq)", s, h, False))
    return trace


def max_activation_bytes(trace: list[tuple[str, int, int, bool]], batch: int) -> int:
    """
    峰值【驻留】激活 = max(需要保存给反向的激活字节数)，BF16 每元素 2 字节。
    g/g* 与 row_out 是瞬态全量张量（存在通信/临时缓冲区里），不计入驻留激活；
    但它们会出现在峰值显存里——面试时要主动区分"驻留激活"与"瞬态缓冲"。
    """
    return max(
        max(batch * s * h * 2 for _, s, h, stored in trace if stored)   # 填空：只统计驻留条目 (stored=True)，b*s*h*2
        for name, s, h, stored in trace
        if stored
    )


def bf16_bytes(s: int, h: int, batch: int) -> int:
    return batch * s * h * 2

三个问答题要点

Q1

  • LayerNorm：μ 与 σ² 沿 h 维求均值/方差（LayerNorm(x) = γ·(x−μ)/√(σ²+ε)+β），每 rank 只有 h/tp 无法算出正确的统计量 → 必须全量 h；
  • dropout：掩码是随机模式，各 rank 必须用相同种子生成一致的掩码（否则激活模式不同步），且掩码要覆盖全量张量；
  • 所以这些”便宜”操作反而是激活内存大户 → 沿序列维切分（SP）把它们也分片。

Q2

  • f/f*（TP 与 DP 交界）：前向 f=no-op（输入已同步）、f*=all-reduce（保证正确性）；反向互换（梯度形状是前向的转置，谁前向是 no-op 谁反向就是 all-reduce）；
  • g/g*（SP 与 TP 交界）：前向 g=all-gather（序列拼回全量）、g*=reduce-scatter（合并 row-linear 的部分和 + 切回序列分片）；反向为共轭互换；
  • SP 区域不用 all-reduce 的原因：all-reduce 需要物化全量激活（先 gather 再 reduce），峰值内存回到 b·s·h，SP 的初衷就没了；用 reduce-scatter 把”求和”与”切分”一步完成。

Q3

  • 由第 3 课：all-reduce = reduce-scatter + all-gather，通信量各半；
  • 纯 TP 每 block：2 次 all-reduce = 通信量 2·(K)；TP+SP：2 all-gather + 2 reduce-scatter = 2·(K/2) + 2·(K/2) = 2K——总量相同，只是操作数翻倍；
  • 所以 SP 的额外代价主要是实现复杂度和更多小消息（latency 略增），带宽成本与 TP 相同；这就是”SP 几乎免费”。

通过要点

  • 术语：本书 SP 专指 TP 的配套技术（LN/dropout 沿序列切）；独立的序列切分叫 CP（第 8 课）。
  • 激活形状：TP 区域 h 切、SP 区域 s 切；驻留激活峰值 b·s·h/tp；g/g* 的瞬态全量张量只存在于通信/临时缓冲区（面试要主动区分）。

### 1. 术语澄清：Megatron-SP 与 Context Parallelism (CP) 的本质区别

在大模型分布式系统领域，“序列并行（Sequence Parallelism）”这个词在历史上有两种完全不同的含义，面试与系统设计中极易混淆：
1. **Megatron-SP（Korthikanti et al., 2022，本课核心）**：专指与**机内张量并行（TP）深度绑定**的优化技术。它并不改变注意力机制的计算拓扑，而是专门针对 Transformer 中未被 TP 覆盖的区域（如 LayerNorm、RMSNorm、Dropout、残差连接等），通过沿序列维度（Sequence Dimension）切分来彻底消除其显存冗余。
2. **Context Parallelism（CP / 环形注意力 Ring-Attention，第 8 课）**：专指跨物理节点将全模型的长文本序列（如 32k、128k、1M 上下文）整体切分并分布式流转计算的独立并行维度。

在讨论序列并行时，必须首先明确其上下文语境。

### 2. 传统 TP 的显存软肋：非 TP 区域的激活冗余

回顾第 6 课，张量并行（TP）成功将 MLP 和 Attention 核心的 GEMM 权重切分到各个 GPU 上，其内部中间激活张量的隐藏维度也被切分为 $\frac{h}{\text{TP}}$。

然而，如**图 7-1** 的对比所示，在 GEMM 算子之外的**非 TP 区域**，系统面临严峻的显存回弹：
- **LayerNorm / RMSNorm 的归一化计算**：
  $$\mu = \frac{1}{h} \sum_{i=1}^h x_i, \quad \sigma^2 = \frac{1}{h} \sum_{i=1}^h (x_i - \mu)^2, \quad \text{LayerNorm}(x) = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} \odot \gamma + \beta$$
  均值 $\mu$ 与方差 $\sigma^2$ 是沿着**整个隐藏特征维度 $h$** 进行统计约简的。若沿 $h$ 维度切分输入，各卡仅持有一部分通道特征，根本无法独立计算出正确的均值和方差，除非在 LayerNorm 内部强行插入跨卡通信。
- **全量激活冗余驻留**：为了避免在每个 Norm 算子内发生低效的跨卡通信，原生 Megatron-LM 规定：在进入 LayerNorm、Dropout 以及残差连接之前，必须持有全量的特征张量 $(b, s, h)$。
- **后果**：这意味着每个 TP 副本的 GPU 显存内都完整保存了一份完全相同的 $(b, s, h)$ 激活张量。随着模型层数 $L$ 与上下文长度 $s$ 的增长，这些未被切分的“公共激活值”占据了反向保留激活（Stored Activations）总量的 30%~50%，严重抵消了 TP 带来的显存收益。

### 3. 序列切分与通信共轭对（$f/f^*$ 与 $g/g^*$ 原语闭环）

Megatron-SP 捕捉到了一个核心数学事实：**LayerNorm、RMSNorm、GELU 和 Dropout 均是逐 Token（Token-wise）独立执行的算子！**
它们在序列维度 $s$ 上没有任何交叉依赖——第 1 个 Token 的归一化结果与第 100 个 Token 的归一化完全互不影响。

因此，完全可以**沿序列维度 $s$ 将非 TP 区域的张量均分为 $\frac{s}{\text{TP}}$ 块**，让每张卡仅驻留 $(b, \frac{s}{\text{TP}}, h)$ 的局部序列激活！

为了在 SP 区域（序列切分）与 TP 区域（隐藏维切分）之间无缝转换，Megatron 引入了优雅的**共轭算子对（Conjugate Operator Pairs）**，其执行拓扑如**图 7-2** 所示：

#### A. $g$ 与 $g^*$ 算子对（SP 与 TP 区域的转换核心）
- **前向转入 TP 区域（$g$ 算子）**：
  - 在进入 Attention / MLP 的列并行矩阵乘之前，算子需要完整的 Token 语义（例如 Attention QKV 投影需与整体位置编码配合）。
  - 系统发起一次 **All-Gather(沿序列维度 $s$)**：
    $$(b, \frac{s}{\text{TP}}, h) \xrightarrow{g = \text{All-Gather}(s)} (b, s, h)$$
  - 随后直接送入列并行线性层，输出沿隐藏维切分的张量 $(b, s, \frac{h}{\text{TP}})$。
- **前向转出 TP 区域（$g^*$ 算子）**：
  - 行并行线性层计算后，各卡产生了部分和张量 $(b, s, h)$。
  - 在原生 TP 中，此处必须执行一次 AllReduce 沿 $h$ 恢复完整和。
  - **而在 SP 中，此处直接替换为 Reduce-Scatter(沿序列维度 $s$)**：
    $$(b, s, \frac{h}{\text{TP}}) \xrightarrow{\text{Row Linear}} (b, s, h) \xrightarrow{g^* = \text{Reduce-Scatter}(s)} (b, \frac{s}{\text{TP}}, h)$$
  - **一石二鸟**：`Reduce-Scatter` 既完成了行并行部分和的累加求和，又顺手将输出张量切分回了 $(b, \frac{s}{\text{TP}}, h)$，直接喂给后续的 LayerNorm 与 Dropout！

#### B. 共轭算子的反向行为与对偶性
在自动微分（Autograd）中，反向求导是前向有向无环图的伴随转置：
- 前向执行 $g$（All-Gather 沿 $s$），反向求导对应的梯度汇聚算子正是其转置对偶：**Reduce-Scatter 沿 $s$**。
- 前向执行 $g^*$（Reduce-Scatter 沿 $s$），反向求导对应的梯度恢复算子正是其转置对偶：**All-Gather 沿 $s$**。
- 这种代数上的高度自洽保证了前向与反向在数学上严格等价，完全无须破坏自动求导链条。

### 4. 通信量守恒定理：为什么 SP 几乎是“免费的午餐”？

直觉上，引入更多的通信算子会导致通信耗时增加。但严格的集合通信带宽分析证明：**Megatron-SP 没有增加任何网络传输字节量！**

回顾第 3 课的核心结论：在 Ring 环形通信算法下，一次 AllReduce 在底层完全等价于一次 Reduce-Scatter 紧接一次 All-Gather：
$$\text{AllReduce}(X) \equiv \text{All-Gather}(\text{Reduce-Scatter}(X))$$
其单步通信字节数关系为：
$$V_{\text{AllReduce}} = 2 \times \frac{\text{TP} - 1}{\text{TP}} \times \text{Size}, \quad V_{\text{Reduce-Scatter}} = V_{\text{All-Gather}} = \frac{\text{TP} - 1}{\text{TP}} \times \text{Size}$$

- **纯 TP 模式每 Block 通信量**：
  前向包含 2 次 AllReduce（Attention 输出 + MLP 输出）：
  $$V_{\text{TP}} = 2 \times V_{\text{AllReduce}} = 4 \times \frac{\text{TP}-1}{\text{TP}} \times (b \cdot s \cdot h \cdot 2)$$
- **TP + SP 模式每 Block 通信量**：
  前向包含 2 次 All-Gather（进入 Col Linear）+ 2 次 Reduce-Scatter（退出 Row Linear）：
  $$V_{\text{TP+SP}} = 2 \times (V_{\text{All-Gather}} + V_{\text{Reduce-Scatter}}) = 4 \times \frac{\text{TP}-1}{\text{TP}} \times (b \cdot s \cdot h \cdot 2)$$

- **重要结论**：$V_{\text{TP+SP}} \equiv V_{\text{TP}}$！两者的**通信总量完全相等**。
  - 虽然网络操作次数翻倍（从 2 次大包变成 4 次半包），但通信数据量被严格均摊。
  - 在机内高速 NVLink 环境下，多出发射两次小集合通信的延迟开销（约 $2\mu s$）微乎其微。
  - 作为回报，模型所有非 TP 区域的驻留激活显存被**直接消减了 $\text{TP}$ 倍**（例如 8 卡下直接砍掉 87.5% 激活显存）。

## 具体演示与数值推演

以一个 70B 模型（隐藏层维度 $h=8192$，层数 $L=80$），在 $\text{TP}=8$、序列长度 $s=16384$（16k 上下文）、单卡批次 $\text{MBS}=1$（BF16 精度，每元素 2 字节）下的单层驻留激活为例：

- **未开启 SP（原生 TP-only）**：
  每个 Block 内的 LayerNorm 与 Dropout 输入张量必须完整物化，单层静态驻留激活为：
  $$M_{\text{act/layer}} \approx 1 \times 16384 \times 8192 \times 2\text{ 字节} \approx 268.4\text{ MB}$$
  全网 80 层累加的静态常驻激活高达：
  $$M_{\text{total\_act}} \approx 80 \times 268.4\text{ MB} \approx 21.5\text{ GB}$$
  在 80GB 显卡上，仅这部分未切分的冗余激活就吃掉了超过四分之一的宝贵显存空间。

- **开启 SP（TP + SP 协同）**：
  LayerNorm 与 Dropout 的输入切为 $(1, \frac{16384}{8}, 8192) = (1, 2048, 8192)$，单层驻留激活降为：
  $$M_{\text{act/layer\_SP}} \approx 1 \times 2048 \times 8192 \times 2\text{ 字节} \approx 33.55\text{ MB} \quad (\text{仅为原来的 } 1/8)$$
  80 层累计驻留激活仅需约 $2.68\text{ GB}$！直接省出近 $19\text{ GB}$ 显存，足以容纳更长的上下文或成倍增加训练 Batch Size。

def trace_block(
    seq: int, hidden: int, tp: int, enable_sp: bool, batch: int = 1,
) -> list[tuple[str, int, int]]:
    """
    返回 [(区域名, s, h)]：前向经过 block 时激活形状的轨迹（每 token 两字节 BF16 可算字节数）。

    算子表（对 (s, h) 的作用）：
      split_seq    : s -> s/tp      （SP 区入口 / g* 出口）
      gather_seq   : s -> s*tp      （g：SP -> TP）
      split_hidden : h -> h/tp      （col-linear 切 h）
      gather_hidden: h -> h*tp      （row-linear 恢复 h）
      noop         : 不变

    区域顺序：
      layernorm → col_linear → gelu → row_linear → dropout
    """
    def split_seq(s, h): return (s // tp, h)
    def gather_seq(s, h): return (s * tp, h)
    def split_hidden(s, h): return (s, h // tp)
    def gather_hidden(s, h): return (s, h * tp)
    def noop(s, h): return (s, h)

    region_ops = {
        "layernorm": noop,   # 填空：TP-only 下 LN 输入就是全量 (s,h)，用什么算子？
        "col_linear": split_hidden,  # 填空：col-linear 沿隐藏维切分
        "gelu": noop,        # 填空：逐元素，形状不变
        "row_linear": gather_hidden,  # 填空：row-linear 恢复隐藏维
        "dropout": noop,     # 填空：TP-only 下 dropout 保持全量
    }
    sp_ops = {
        # 启用 SP 时各区域用的算子（提示：LN/dropout 在 SP 区沿序列切，
        # col/row 在 TP 区沿隐藏维切）
        "layernorm": split_seq,
        "col_linear": split_hidden,
        "gelu": noop,
        "row_linear": gather_hidden,
        "dropout": noop,
    }

        persists = not (enable_sp and name == "row_linear")

            trace.append(("g* (reduce-scatter seq)", s, h, False))

## 三个问答题要点

### Q1

- LayerNorm：μ 与 σ² 沿 h 维求均值/方差（`LayerNorm(x) = γ·(x−μ)/√(σ²+ε)+β`），每 rank 只有 h/tp 无法算出正确的统计量 → 必须全量 h；
- dropout：掩码是随机模式，各 rank 必须用相同种子生成一致的掩码（否则激活模式不同步），且掩码要覆盖全量张量；
- 所以这些"便宜"操作反而是激活内存大户 → 沿序列维切分（SP）把它们也分片。

### Q2

- f/f\*（TP 与 DP 交界）：前向 f=no-op（输入已同步）、f\*=all-reduce（保证正确性）；反向互换（梯度形状是前向的转置，谁前向是 no-op 谁反向就是 all-reduce）；
- g/g\*（SP 与 TP 交界）：前向 g=all-gather（序列拼回全量）、g\*=reduce-scatter（合并 row-linear 的部分和 + 切回序列分片）；反向为共轭互换；
- SP 区域不用 all-reduce 的原因：all-reduce 需要物化全量激活（先 gather 再 reduce），峰值内存回到 b·s·h，SP 的初衷就没了；用 reduce-scatter 把"求和"与"切分"一步完成。

### Q3

- 由第 3 课：all-reduce = reduce-scatter + all-gather，通信量各半；
- 纯 TP 每 block：2 次 all-reduce = 通信量 2·(K)；TP+SP：2 all-gather + 2 reduce-scatter = 2·(K/2) + 2·(K/2) = 2K——总量相同，只是操作数翻倍；
- 所以 SP 的额外代价主要是实现复杂度和更多小消息（latency 略增），带宽成本与 TP 相同；这就是"SP 几乎免费"。

## 通过要点

- 术语：本书 SP 专指 TP 的配套技术（LN/dropout 沿序列切）；独立的序列切分叫 CP（第 8 课）。
- 激活形状：TP 区域 h 切、SP 区域 s 切；**驻留**激活峰值 b·s·h/tp；g/g* 的瞬态全量张量只存在于通信/临时缓冲区（面试要主动区分）。
