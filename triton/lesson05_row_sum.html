第 5 课：行归约：Padding 单位元与均值方差

本课目标与完成标准

学完后你应能：写出一 program 一行的行归约、给 padding 选对单位元、用 mask 正确传播到均值/方差，并说明两遍法与单遍法的取舍。

通过必须同时满足：代码填空通过全部断言；Q1～Q3 说明因果链；能指出一个单位元不变量和一个精度取舍；总分不低于 8/10。

前置关系

  • 前置：Triton 第 1 课（program/mask）、CUDA 第 2 课（归约）
  • 本课位置：行归约是 RMSNorm / Softmax 的内核骨架；本课的 mask 传播与单位元选择在第 7 课（Softmax）直接复用。

核心心智模型

1. 二维网格：一 program 一行

@triton.jit
def row_sum_kernel(x_ptr, out_ptr, n_cols, BLOCK_N: tl.constexpr):
    row = tl.program_id(0)
    cols = tl.arange(0, BLOCK_N)
    mask = cols < n_cols
    x = tl.load(x_ptr + row * n_cols + cols, mask=mask, other=0.0)
    tl.store(out_ptr + row, tl.sum(x, axis=0))

要点： - program_id(0) 是行号，列方向由 tl.arange 一次铺开； - BLOCK_N 通常取 ≥n_cols\ge n\_cols 的 2 的幂（如 2048），多出来的列被 mask 掉； - tl.sum(x, axis=0) 把整块折成一个标量。

2. Padding 的单位元：归约的身份元素

被 mask 的位置仍然存在于向量里，会参与 tl.sum。所以 other 必须是该归约的单位元：

归约 单位元 选错的后果
tl.sum 0.0 取 1.0 会凭空多加上百
tl.max -inf 取 0.0 时全负行会返回 0
tl.min +inf 取 0.0 时全正行会返回 0
乘积 1.0 取 0.0 结果恒为 0

这是「掩码值参与计算」与 CUDA 里「线程直接不参与」的关键差别：CUDA 靠分支跳过，Triton 靠单位元吸收。

3. 均值与方差：mask 要传播到分母

y=x−μσ2+ϵ,μ=1N∑xi,σ2=1N∑(xi−μ)2y = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}},\qquad \mu=\frac{1}{N}\sum x_i,\quad \sigma^2=\frac{1}{N}\sum (x_i-\mu)^2

Triton 里最容易错的是分母：tl.sum(x) 里 padding 贡献了 0，但如果你直接除以 BLOCK_N，等于把 padding 当成了真实样本，均值被系统性压低。

正确做法是除以有效元素数：

count = tl.sum(mask.to(tl.float32), axis=0)   # 有效列数
mean = tl.sum(x, axis=0) / count

同理方差也要用同一个 count，而不是 BLOCK_N。

4. 两遍法 vs 单遍法

  • 两遍法：先算 mean，再算 ∑(x−μ)2\sum (x-\mu)^2。需要把整行留在寄存器/再次读取，但数值稳定。
  • 单遍法（两矩）：σ2=𝔼[x2]−μ2\sigma^2 = \mathbb{E}[x^2]-\mu^2。只需一次归约，但当数据「大均值、小方差」时两个大数相减会丢失有效位，甚至算出负方差（详见 CUDA 第 4 课）。若采用，必须 tl.maximum(var, 0.0) 截断。
  • Welford：单遍且稳定，代价是每次归约要传三个量。

Triton 里常见折中：行长度不大（≤\le 几 K）时直接用两遍法，把整行留在寄存器，代价可接受。

5. 正确性不变量

  1. 单位元与归约匹配（见上表）。
  2. 分母是有效元素数，不是 BLOCK_N。
  3. mask 是布尔张量，转 float 才能求和：mask.to(tl.float32)，直接 tl.sum(mask) 在部分版本上类型不匹配。
  4. ϵ\epsilon 加在开方之前（同 CUDA 第 4 课）。
  5. BLOCK_N < n_cols 时必须循环：若列数超过块宽，单次 tl.arange 覆盖不全，需要 for 循环累加，否则静默漏算。

6. 工程取舍

  • BLOCK_N 取多大：取到刚好覆盖 n_colsn\_cols 的 2 的幂最省事；若 n_colsn\_cols 变化很大（如 512～8192），固定大块会浪费大量被 mask 的槽位，此时按 shape 分桶或改成循环更划算。
  • 一 program 一行 vs 一 program 多行：行数很多、每行很短时，一行一个 program 会让每个 program 的有效工作太少，可以改成一块处理多行（ROWS_PER_BLOCK），代价是寄存器压力上升。

具体演示：mask 与分母

设 n_cols=5n\_cols = 5，BLOCK_N = 8，某行 x=[1,2,3,4,5]x = [1,2,3,4,5]，padding 三格。

  • x 在 kernel 里是 [1,2,3,4,5,0,0,0]（other=0.0）
  • tl.sum(x) = 15，正确
  • 若除以 BLOCK_N=8：μ=1.875\mu = 1.875（错）；除以有效数 5：μ=3\mu = 3（对）
  • 方差：∑(xi−3)2=4+1+0+1+4=10\sum (x_i-3)^2 = 4+1+0+1+4 = 10，除以 5 得 22；若除以 8 得 1.251.25

误差不是舍入级的，而是 30%+ 的系统性偏差——这类 bug 会让训练 loss 缓慢偏高，很难归因。

import numpy as np

def row_sum_masked(row, block_n):
    n = len(row)
    padded = np.full(block_n, 0.0, dtype=np.float64)
    padded[:n] = row
    return padded.sum()

def row_mean_var(row, block_n, eps=1e-6):
    n = len(row)
    padded = np.zeros(block_n, dtype=np.float64)
    padded[:n] = row
    mask = np.arange(block_n) < n
    count = mask.sum()
    mean = padded.sum() / count
    dev = np.where(mask, padded - mean, 0.0)
    var = (dev ** 2).sum() / count
    return mean, var

def row_max_masked(row, block_n):
    n = len(row)
    padded = np.full(block_n, -np.inf, dtype=np.float64)
    padded[:n] = row
    return padded.max()

assert abs(mean - 3.0) < 1e-12
assert abs(var - 2.0) < 1e-12
assert row_max_masked([-3., -1., -2.], 8) == -1.0

Q1 参考答案

  1. CUDA 靠分支：if (i < n) 直接让越界线程不参与，归约树里这些线程贡献 0（或被跳过），不需要额外约定。
  2. Triton 是向量化块运算：没有逐元素分支，mask 只是把值替换成 other，这些位置仍然进入归约。所以必须让 other 在数学上不改变结果，这就是单位元。
  3. 代价差异：CUDA 的分支会造成 Warp 内分歧（尾块尤其明显），Triton 的 mask 是算术替换、无分歧，但要求开发者显式选对单位元；另外 mask 掉的位置仍然占用寄存器与计算槽位，块越大浪费越多。

Q2 参考答案

  1. padding 是「假样本」：它们贡献 0 到分子，却不该计入分母。用 BLOCK_N 相当于把它们当成取值为 0 的真实观测。
  2. 偏差量级：本例 n=5n=5、BLOCK_N=8，均值从 3 变成 1.875（偏低 37.5%），方差从 2 变成 1.25（偏低 37.5%）。偏差比例约等于 (BLOCKN−n)/BLOCKN(BLOCK_N-n)/BLOCK_N，块越大越严重。
  3. 表现：训练时 loss 偏高且下降缓慢、Norm 层输出尺度不对；推理时不同 batch 长度给出不同结果（因为 BLOCK_N 与有效长度的比例变了），是最典型的「静默错误」。

Q3 参考答案

  1. 问题一：覆盖不全。tl.arange(0, BLOCK_N) 最多覆盖 BLOCK_N 列，超过的列不会被读到，结果是静默漏算（不是报错）。
  2. 问题二：寄存器压力。为了单次覆盖整行而把 BLOCK_N 开到 8192，会让每个 program 占用大量寄存器，Occupancy 掉下来，反而更慢。
  3. 改法：用 for k in range(0, n_cols, BLOCK_N) 循环累加，块内仍用 mask 处理最后一块；累加器保持在寄存器里，最后再算均值/方差。若行数很多，还可以一个 program 处理多行（ROWS_PER_BLOCK）以提高有效工作量。

学完后你应能：写出一 program 一行的行归约、给 padding 选对单位元、用 mask 正确传播到均值/方差，并说明两遍法与单遍法的取舍。

通过必须同时满足：代码填空通过全部断言；Q1～Q3 说明因果链；能指出一个单位元不变量和一个精度取舍；总分不低于 8/10。

## 前置关系

- 前置：Triton 第 1 课（program/mask）、CUDA 第 2 课（归约）
- 本课位置：行归约是 RMSNorm / Softmax 的内核骨架；本课的 mask 传播与单位元选择在第 7 课（Softmax）直接复用。

## 核心心智模型

### 1. 二维网格：一 program 一行

```python
@triton.jit
def row_sum_kernel(x_ptr, out_ptr, n_cols, BLOCK_N: tl.constexpr):
    row = tl.program_id(0)
    cols = tl.arange(0, BLOCK_N)
    mask = cols < n_cols
    x = tl.load(x_ptr + row * n_cols + cols, mask=mask, other=0.0)
    tl.store(out_ptr + row, tl.sum(x, axis=0))
```

要点：
- `program_id(0)` 是行号，列方向由 `tl.arange` 一次铺开；
- `BLOCK_N` 通常取 $\ge n\_cols$ 的 2 的幂（如 2048），多出来的列被 mask 掉；
- `tl.sum(x, axis=0)` 把整块折成一个标量。

### 2. Padding 的单位元：归约的身份元素

被 mask 的位置仍然存在于向量里，会参与 `tl.sum`。所以 `other` 必须是该归约的**单位元**：

| 归约 | 单位元 | 选错的后果 |
|---|---|---|
| `tl.sum` | `0.0` | 取 1.0 会凭空多加上百 |
| `tl.max` | `-inf` | 取 0.0 时全负行会返回 0 |
| `tl.min` | `+inf` | 取 0.0 时全正行会返回 0 |
| 乘积 | `1.0` | 取 0.0 结果恒为 0 |

这是「掩码值参与计算」与 CUDA 里「线程直接不参与」的关键差别：CUDA 靠分支跳过，Triton 靠单位元吸收。

### 3. 均值与方差：mask 要传播到分母

$$y = \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}},\qquad \mu=\frac{1}{N}\sum x_i,\quad \sigma^2=\frac{1}{N}\sum (x_i-\mu)^2$$

Triton 里最容易错的是**分母**：`tl.sum(x)` 里 padding 贡献了 0，但如果你直接除以 `BLOCK_N`，等于把 padding 当成了真实样本，均值被系统性压低。

正确做法是除以**有效元素数**：

```python
count = tl.sum(mask.to(tl.float32), axis=0)   # 有效列数
mean = tl.sum(x, axis=0) / count
```

同理方差也要用同一个 `count`，而不是 `BLOCK_N`。

### 4. 两遍法 vs 单遍法

- **两遍法**：先算 `mean`，再算 $\sum (x-\mu)^2$。需要把整行留在寄存器/再次读取，但数值稳定。
- **单遍法（两矩）**：$\sigma^2 = \mathbb{E}[x^2]-\mu^2$。只需一次归约，但当数据「大均值、小方差」时两个大数相减会丢失有效位，甚至算出负方差（详见 CUDA 第 4 课）。若采用，必须 `tl.maximum(var, 0.0)` 截断。
- **Welford**：单遍且稳定，代价是每次归约要传三个量。

Triton 里常见折中：行长度不大（$\le$ 几 K）时直接用两遍法，把整行留在寄存器，代价可接受。

### 5. 正确性不变量

1. **单位元与归约匹配**（见上表）。
2. **分母是有效元素数**，不是 `BLOCK_N`。
3. **mask 是布尔张量，转 float 才能求和**：`mask.to(tl.float32)`，直接 `tl.sum(mask)` 在部分版本上类型不匹配。
4. **$\epsilon$ 加在开方之前**（同 CUDA 第 4 课）。
5. **`BLOCK_N < n_cols` 时必须循环**：若列数超过块宽，单次 `tl.arange` 覆盖不全，需要 `for` 循环累加，否则静默漏算。

### 6. 工程取舍

- **BLOCK_N 取多大**：取到刚好覆盖 $n\_cols$ 的 2 的幂最省事；若 $n\_cols$ 变化很大（如 512～8192），固定大块会浪费大量被 mask 的槽位，此时按 shape 分桶或改成循环更划算。
- **一 program 一行 vs 一 program 多行**：行数很多、每行很短时，一行一个 program 会让每个 program 的有效工作太少，可以改成一块处理多行（`ROWS_PER_BLOCK`），代价是寄存器压力上升。

## 具体演示：mask 与分母

设 $n\_cols = 5$，`BLOCK_N = 8`，某行 $x = [1,2,3,4,5]$，padding 三格。

- `x` 在 kernel 里是 `[1,2,3,4,5,0,0,0]`（`other=0.0`）
- `tl.sum(x) = 15`，正确
- 若除以 `BLOCK_N=8`：$\mu = 1.875$（错）；除以有效数 5：$\mu = 3$（对）
- 方差：$\sum (x_i-3)^2 = 4+1+0+1+4 = 10$，除以 5 得 $2$；若除以 8 得 $1.25$

误差不是舍入级的，而是 30%+ 的系统性偏差——这类 bug 会让训练 loss 缓慢偏高，很难归因。

::: {#triton_l05_solution .cell course_role='solution' execution_count=1}
```python
import numpy as np

def row_sum_masked(row, block_n):
    n = len(row)
    padded = np.full(block_n, 0.0, dtype=np.float64)
    padded[:n] = row
    return padded.sum()

def row_mean_var(row, block_n, eps=1e-6):
    n = len(row)
    padded = np.zeros(block_n, dtype=np.float64)
    padded[:n] = row
    mask = np.arange(block_n) < n
    count = mask.sum()
    mean = padded.sum() / count
    dev = np.where(mask, padded - mean, 0.0)
    var = (dev ** 2).sum() / count
    return mean, var

def row_max_masked(row, block_n):
    n = len(row)
    padded = np.full(block_n, -np.inf, dtype=np.float64)
    padded[:n] = row
    return padded.max()

assert row_sum_masked([1., 2., 3., 4., 5.], 8) == 15.0
mean, var = row_mean_var([1., 2., 3., 4., 5.], 8)
assert abs(mean - 3.0) < 1e-12
assert abs(var - 2.0) < 1e-12
assert row_max_masked([-3., -1., -2.], 8) == -1.0
for b in (5, 8, 16):
    m, v = row_mean_var([1., 2., 3., 4., 5.], b)
    assert abs(m - 3.0) < 1e-12 and abs(v - 2.0) < 1e-12
```

### Q1 参考答案

1. **CUDA 靠分支**：`if (i < n)` 直接让越界线程不参与，归约树里这些线程贡献 0（或被跳过），不需要额外约定。
2. **Triton 是向量化块运算**：没有逐元素分支，mask 只是把值替换成 `other`，这些位置**仍然进入归约**。所以必须让 `other` 在数学上不改变结果，这就是单位元。
3. **代价差异**：CUDA 的分支会造成 Warp 内分歧（尾块尤其明显），Triton 的 mask 是算术替换、无分歧，但要求开发者显式选对单位元；另外 mask 掉的位置仍然占用寄存器与计算槽位，块越大浪费越多。

### Q2 参考答案

1. **padding 是「假样本」**：它们贡献 0 到分子，却不该计入分母。用 `BLOCK_N` 相当于把它们当成取值为 0 的真实观测。
2. **偏差量级**：本例 $n=5$、`BLOCK_N=8`，均值从 3 变成 1.875（偏低 37.5%），方差从 2 变成 1.25（偏低 37.5%）。偏差比例约等于 $(BLOCK_N-n)/BLOCK_N$，块越大越严重。
3. **表现**：训练时 loss 偏高且下降缓慢、Norm 层输出尺度不对；推理时不同 batch 长度给出不同结果（因为 `BLOCK_N` 与有效长度的比例变了），是最典型的「静默错误」。

### Q3 参考答案

1. **问题一：覆盖不全**。`tl.arange(0, BLOCK_N)` 最多覆盖 `BLOCK_N` 列，超过的列不会被读到，结果是**静默漏算**（不是报错）。
2. **问题二：寄存器压力**。为了单次覆盖整行而把 `BLOCK_N` 开到 8192，会让每个 program 占用大量寄存器，Occupancy 掉下来，反而更慢。
3. **改法**：用 `for k in range(0, n_cols, BLOCK_N)` 循环累加，块内仍用 mask 处理最后一块；累加器保持在寄存器里，最后再算均值/方差。若行数很多，还可以一个 program 处理多行（`ROWS_PER_BLOCK`）以提高有效工作量。
