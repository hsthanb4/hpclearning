阅读路线：

  1. 原始 speculative decoding/sampling 论文：先推导单步分布，再看多 token 连续接受。
  2. vLLM v1/worker/gpu/spec_decode/rejection_sampler.py::_verify：target logits 先经过哪些 sampling params。
  3. rejection_sample kernel 调用：输入 draft logits/tokens、target logits、temperature/seeds 和位置映射。
  4. __call__：理解 ragged logits、chunk verification、num_sampled/num_rejected。
  5. 再回 scheduler：accepted token 数怎样推进 computed/output state，draft tokens 怎样进入下一轮。

源码快照：vLLM 8e958902eee5。

核心对象

Draft distribution 为 q，target distribution 为 p。Draft 先采样候选 x；以 min(1,p(x)/q(x)) 接受。若拒绝，不能直接从 p 重采，而要从校正分布 r(y) ∝ max(p(y)-q(y),0) 采样。这样“接受路径 + 拒绝路径”的总边缘分布恰为 p。

Greedy decoding 是特殊情况：draft token 与 target argmax 连续相等就接受，首次不等处使用 target token。一般 temperature/top-p/penalties 下只比 argmax 会改变分布。

调用链与状态变化

多个 draft tokens 必须从头连续验证：第 i 个 draft 是条件于前 i-1 个 draft 的提案；一旦第 j 个被拒绝并换成校正 token，后续 draft 的条件前缀已失效。若 k 个都接受，target verification 还可给出一个 bonus token，因此每轮通常产出 accepted prefix 加一个 target-correct token。

vLLM 在 _verify 中先对 target logits 应用与请求一致的 penalties、temperature 等，再调用 GPU rejection sample；ragged mapping 把不同请求的 verify 长度映射回状态。正确性不仅是公式，还包括 RNG、logits processor、grammar 和 EOS 的一致性。

正确性条件与常见误区

要求 q 对实际提案 token 有正概率；p/q 必须使用同一词表与处理后的分布；拒绝后 residual 归一化；第一处拒绝后停止使用后续草稿；随机种子/每请求状态不能因 batch 重排串线。

Lossless 的含义是输出分布与 target-only 相同，不等于逐次使用相同 RNG 时字符串一定逐 token 相同；实现可定义更强的 batch invariance，但需额外 RNG 合同。

当前前沿与工程取舍

Speculation 的理论正确性与性能是两件事。高 acceptance length 不保证加速：draft cost、target verify shape、KV/hidden state、sampling kernel、CPU 协调和 batch size 都进入临界路径。高并发时 target verification 可能变重，甚至慢于普通 decode。面试应先证明分布，再建立成本模型。

具体推演

设 p=[0.7,0.3]、q=[0.4,0.6]。draft 提议 token1 时接受率 0.3/0.6=0.5；拒绝后 residual 与 max(p-q,0)=[0.3,0] 成正比，因此必选 token0。接受路径贡献 [0,0.3]，拒绝路径贡献 [0.3,0]，再加 draft 提议 token0 被完全接受的 [0.4,0]，总计正好 [0.7,0.3]。

Q1 参考答案

对 token y，接受路径概率是 q(y)·min(1,p(y)/q(y))=min(p(y),q(y))。总拒绝概率为 1-Σmin(p,q)=Σ(p-q)_+。拒绝后从 r(y)=(p(y)-q(y))_+/Σ(p-q)_+ 采样，贡献 (p(y)-q(y))_+。两项相加 min(p,q)+(p-q)_+=p(y)，因此边缘分布精确等于 target。

Q2 参考答案

它们把原始 logits 变成真正的请求条件分布。如果 target 用处理后 p，而 draft probability/接受率基于另一分布，p/q 与 residual 不再对应同一概率空间；grammar 还可能让某 token 概率变零。结果可能改变输出分布、接受非法 token，或在 batch 重排后出现不可复现错误。源码因此把 sampling states、位置和 request mapping 带入 verifier。

Q3 参考答案

自回归第 i 个 draft 的 q/p 都条件于前面的 draft 前缀。拒绝位置被校正 token 替换后，后续候选是在错误前缀下生成，其条件概率、位置关系和 KV 状态都不再有效；即使 token id 偶然相同，也不能越过已经断裂的条件链。verifier 必须只提交拒绝前的连续接受前缀和本次校正 token，回收其后的临时槽位，再从新前缀开始下一轮 proposal。

自回归第 i 个 draft 的 q/p 都条件于前面的 draft 前缀。拒绝位置被校正 token 替换后，后续候选是在错误前缀下生成，其条件概率、位置关系和 KV 状态都不再有效；即使 token id 偶然相同，也不能越过已经断裂的条件链。verifier 必须只提交拒绝前的连续接受前缀和本次校正 token，回收其后的临时槽位，再从新前缀开始下一轮 proposal。
