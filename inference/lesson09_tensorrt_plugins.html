核心心智模型

1. 为什么工业级端侧部署离不开 TensorRT 自定义插件？

在自动驾驶（如 3D 目标检测、BEV 环视变形注意力、点云体素化）或具身连续控制中，模型中经常包含非标准算子或前沿融合内核（如 Flow Matching 去噪求解器）。标准 ONNX 算子集无法直接表达这些特殊逻辑。

为了让这些算子无缝融入 TensorRT 的图优化流水线（算子融合、显存复用、CUDA Graph 录制），工程师必须实现 TensorRT Plugin（自定义算子插件）。

2. 传统 IPluginV2DynamicExt 的历史缺陷与 IPluginV3 的模块化革新

在 TensorRT 8.x/9.x 中广泛使用的 IPluginV2DynamicExt 是一套庞大而脆弱的单体接口： - 编译期构建逻辑（Supported Formats、Shape Inference）与运行期执行逻辑（enqueue）死死揉在一个臃肿的 C++ 类中； - 序列化（Serialization）极其繁琐，在反序列化时必须重新构造全部构建期状态，导致加载 Engine 时内存膨胀且脆弱易崩。

在现代 TensorRT 10.x 及后续标准中，NVIDIA 全面转向了基于能力解耦（Capability-Based）的 IPluginV3 体系：

图 9-1：TensorRT 10 IPluginV3 模块化能力解耦架构

  • 彻底分离构建与运行：在端侧车辆或机器人部署时，只需加载 IPluginV3OneRuntime 纯执行对象，彻底剥离所有昂贵的编译期元数据，内存开销降低 80% 以上；
  • 支持数据依赖形状（Data-Dependent Shapes）：原生支持输出张量尺寸由计算结果决定的算子（例如 NMS 过滤后的目标数量、稀疏体素数量）。

class CustomTRTPluginV3:
    def __init__(self, name="CustomScaleActPlugin", version="1.0.0"):
        self.name = name
        self.version = version

    def get_output_shapes(self, input_shapes):
        # 逐元素算子，输出形状与输入第 0 个张量严格对齐
        return [tuple(input_shapes[0])]

    def get_workspace_size(self, input_shapes):
        total_elements = 1
        for dim in input_shapes[0]:
            total_elements *= dim
        # 每个 float32 元素需要 4 字节片上临时空间
        return total_elements * 4

    def enqueue(self, inputs, outputs, workspace, scale=2.0):
        x = inputs[0]
        # 1. 第一步：将 ReLU 结果写入临时 workspace 缓冲
        np.maximum(x, 0.0, out=workspace)
        # 2. 第二步：将 scale 缩放结果从 workspace 写入最终 output 空间
        np.multiply(workspace, scale, out=outputs[0])

Q1 参考答案

  1. 计算图时序重叠与生命周期着色（Liveness Analysis）： 在 TensorRT 执行器中，各个网络层在时序上是先后依次执行的。算子 A 计算完毕后，其在 Workspace 中存放的临时特征图生命周期立即结束，这块显存地址可以立刻被后续的算子 B 覆盖重用。
  2. 全局最大峰值分配（Peak Sizing）： TensorRT 在构建引擎时，遍历全图所有算子申报的 getWorkspaceSize()，取所有活跃区间内重叠需求的最大值，在初始化阶段一次性预分配一个全局共享的 Workspace 内存池。几十个算子在执行时仅是轮流借用该内存池的不同偏移区间，将原本可能高达数 GB 的临时显存开销压缩至几十 MB。

Q2 参考答案

  1. CUDA Graph 静态拓扑契约： CUDA Graph 的核心机制是通过一次录制将所有内核的物理指针、Grid 维度与发射参数固化在硬件 Pushbuffer 中。
  2. 禁止动态操作的原因：
    • 若在 enqueue 内部调用 cudaMalloc，不仅会破坏静态地址映射，还会触发驱动级显存锁导致 Graph 录制中断（cudaErrorStreamCaptureUnsupported）；
    • 若调用 cudaStreamSynchronize，会打破异步队列流水线，强行逼停正在并行的其他 Stream。所有中间缓冲必须使用 TensorRT 预先分配好的输入输出指针或 Workspace 指针。

Q3 参考答案

  1. 传统引擎被迫回传 CPU 的瓶颈： 对于 NMS 过滤算子，由于输入每帧检测到的障碍物数量不确定（有时是 5 个，有时是 50 个），传统推理引擎无法为下游跟踪网络分配固定显存，必须将检测计数 count 拷回 CPU，由 Python 动态重新调用 cudaMalloc，导致严重的 Host-Device 同步气泡。
  2. TensorRT 10 片上表达式机制： TensorRT 引入了 IExprBuilder 与符号化张量（Size Tensor）。下游算子将上游插件返回的标量指针直接声明为形状表达式（如 declareSizeTensor），显存分配器在 GPU 内部完成上界的预分配或动态视图偏移，全程零 CPU 介入，在纯 GPU 硬件管线内无缝支持动态数据驱动图。

```python
class CustomTRTPluginV3:
    def __init__(self, name="CustomScaleActPlugin", version="1.0.0"):
        self.name = name
        self.version = version

    def get_output_shapes(self, input_shapes):
        # 逐元素算子，输出形状与输入第 0 个张量严格对齐
        return [tuple(input_shapes[0])]

    def get_workspace_size(self, input_shapes):
        total_elements = 1
        for dim in input_shapes[0]:
            total_elements *= dim
        # 每个 float32 元素需要 4 字节片上临时空间
        return total_elements * 4

    def enqueue(self, inputs, outputs, workspace, scale=2.0):
        x = inputs[0]
        # 1. 第一步：将 ReLU 结果写入临时 workspace 缓冲
        np.maximum(x, 0.0, out=workspace)
        # 2. 第二步：将 scale 缩放结果从 workspace 写入最终 output 空间
        np.multiply(workspace, scale, out=outputs[0])
```

### Q1 参考答案

1. **计算图时序重叠与生命周期着色（Liveness Analysis）**：
   在 TensorRT 执行器中，各个网络层在时序上是先后依次执行的。算子 A 计算完毕后，其在 Workspace 中存放的临时特征图生命周期立即结束，这块显存地址可以立刻被后续的算子 B 覆盖重用。
2. **全局最大峰值分配（Peak Sizing）**：
   TensorRT 在构建引擎时，遍历全图所有算子申报的 `getWorkspaceSize()`，取所有活跃区间内重叠需求的最大值，在初始化阶段一次性预分配一个全局共享的 Workspace 内存池。几十个算子在执行时仅是轮流借用该内存池的不同偏移区间，将原本可能高达数 GB 的临时显存开销压缩至几十 MB。

### Q2 参考答案

1. **CUDA Graph 静态拓扑契约**：
   CUDA Graph 的核心机制是通过一次录制将所有内核的物理指针、Grid 维度与发射参数固化在硬件 Pushbuffer 中。
2. **禁止动态操作的原因**：
   - 若在 `enqueue` 内部调用 `cudaMalloc`，不仅会破坏静态地址映射，还会触发驱动级显存锁导致 Graph 录制中断（`cudaErrorStreamCaptureUnsupported`）；
   - 若调用 `cudaStreamSynchronize`，会打破异步队列流水线，强行逼停正在并行的其他 Stream。所有中间缓冲必须使用 TensorRT 预先分配好的输入输出指针或 Workspace 指针。

### Q3 参考答案

1. **传统引擎被迫回传 CPU 的瓶颈**：
   对于 NMS 过滤算子，由于输入每帧检测到的障碍物数量不确定（有时是 5 个，有时是 50 个），传统推理引擎无法为下游跟踪网络分配固定显存，必须将检测计数 `count` 拷回 CPU，由 Python 动态重新调用 `cudaMalloc`，导致严重的 Host-Device 同步气泡。
2. **TensorRT 10 片上表达式机制**：
   TensorRT 引入了 `IExprBuilder` 与符号化张量（Size Tensor）。下游算子将上游插件返回的标量指针直接声明为形状表达式（如 `declareSizeTensor`），显存分配器在 GPU 内部完成上界的预分配或动态视图偏移，全程零 CPU 介入，在纯 GPU 硬件管线内无缝支持动态数据驱动图。
