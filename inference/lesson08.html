方案族：

  • N-gram/suffix：无需训练，复用上下文重复模式，便宜但依赖文本可预测性。
  • Standalone draft：小模型自回归提案，通用但有额外权重/KV和串行 draft。
  • MTP：目标模型原生多 token heads/模块，部署紧耦合、额外模型较小。
  • EAGLE-3：使用 target 多层特征并直接预测 token，autoregressive/tree draft 后并行 verify。
  • DFlash：轻量 block-diffusion drafter 并行生成一个 block，减少串行 drafting。
  • DSpark：源码中体现 confidence-scheduled/adaptive draft budget 与 ragged verify，目标是按请求难度减少无效 verify。

这些名称描述 proposal 机制；lossless 仍依赖上一课的 target verification。

调用链与状态变化

EAGLE V2 worker 从 target hidden/token 状态构造 draft input，多步/top-k 扩展成 tree，再构建 target verify mask；verify 返回 accepted tokens、bonus 和下一轮 draft 状态。DFlash prefill 捕获 target auxiliary hidden states并写 draft KV，decode 时产生 block proposal、target verify、提交接受前缀并构造下一 block。DSpark 为不同请求选择不同 draft/verify 长度，因此需要 ragged layout、bucketed CUDA graph 和 confidence relay。

Overlap scheduling 尝试让 CPU 结果处理、draft/verify 或下一 batch 准备重叠，但共享 hidden/KV/buffer 的 WAR、shape bucket 和 grammar barrier 都是正确性条件。

正确性条件与常见误区

不能只比较 acceptance rate：应分别记录 accepted drafts、每轮产出 token、draft time、verify time、sampling/CPU overhead、额外显存、batch size、prompt/output 分布和 SLO goodput。论文的单请求 greedy speedup不等于高并发服务收益。

方案必须与 target tokenizer/vocab、hidden interface、model revision 和 sampling features兼容。源码中枚举存在不代表所有硬件、模型、PP/PD/LoRA/grammar 组合都成熟。

当前前沿与工程取舍

截至本快照，EAGLE-3 是成熟高接受率的训练式路线；DFlash 代表并行 block draft 的新前沿；DSpark/自适应 speculation 代表按位置、请求和 batch 动态调深度。论文报告可作为候选证据，最终选型没有统一冠军：高 batch、长 reasoning、开放式采样、代码重复和不同 GPU 会改变成本。最先进的工程实践是可观测、可回退的自适应策略，而不是固定最大 draft length。

具体推演

若每个 draft 位置的条件接受率是 [0.8,0.7,0.5]，期望接受 draft 数为 0.8 + 0.8×0.7 + 0.8×0.7×0.5 = 1.64；加上拒绝校正或全接受后的 bonus，每轮期望产出 2.64 tokens。若 draft+verify+overhead 比 target-only 生成 2.64 tokens 还慢，acceptance 看起来不错也没有端到端加速。

Q1 参考答案

EAGLE-3 使用 target 多层特征的轻量 draft，通常仍自回归/树式扩展多个步骤；MTP 使用目标模型原生额外预测模块/heads，省独立大 draft 但与模型结构紧耦合；DFlash 用 block-diffusion drafter 并行提出一块 token，试图去掉串行 draft 深度。三者都需 target verify，额外 KV/hidden、kernel shape 和可支持模型集合不同。

Q2 参考答案

位置、请求类型、temperature、batch 和生成长度会改变接受率；更深 proposal 增加 draft、verify token、KV和 graph bucket，低接受时大部分工作被拒绝。自适应策略根据近期 accepted length/置信度和成本选择预捕获 tier，在收益不足时回退普通 decode，才能维持 SLO goodput。

Q3 参考答案

固定 engine commit、模型/draft revision、硬件/功耗和 sampling 参数；使用生产 prompt/output/到达分布的 open-loop 压测，覆盖不同 batch、长输出、代码与开放文本。记录 TTFT、ITL/p99、output tok/s、SLO goodput、accepted drafts/tokens、draft/verify/CPU时间、显存和失败。与同 engine 的 target-only baseline 比较，并报告 warmup、CUDA graph、质量/分布等价验证和不加速区域。

若每个 draft 位置的条件接受率是 `[0.8,0.7,0.5]`，期望接受 draft 数为 `0.8 + 0.8×0.7 + 0.8×0.7×0.5 = 1.64`；加上拒绝校正或全接受后的 bonus，每轮期望产出 2.64 tokens。若 draft+verify+overhead 比 target-only 生成 2.64 tokens 还慢，acceptance 看起来不错也没有端到端加速。

### Q1 参考答案

EAGLE-3 使用 target 多层特征的轻量 draft，通常仍自回归/树式扩展多个步骤；MTP 使用目标模型原生额外预测模块/heads，省独立大 draft 但与模型结构紧耦合；DFlash 用 block-diffusion drafter 并行提出一块 token，试图去掉串行 draft 深度。三者都需 target verify，额外 KV/hidden、kernel shape 和可支持模型集合不同。

### Q2 参考答案

位置、请求类型、temperature、batch 和生成长度会改变接受率；更深 proposal 增加 draft、verify token、KV和 graph bucket，低接受时大部分工作被拒绝。自适应策略根据近期 accepted length/置信度和成本选择预捕获 tier，在收益不足时回退普通 decode，才能维持 SLO goodput。

### Q3 参考答案

固定 engine commit、模型/draft revision、硬件/功耗和 sampling 参数；使用生产 prompt/output/到达分布的 open-loop 压测，覆盖不同 batch、长输出、代码与开放文本。记录 TTFT、ITL/p99、output tok/s、SLO goodput、accepted drafts/tokens、draft/verify/CPU时间、显存和失败。与同 engine 的 target-only baseline 比较，并报告 warmup、CUDA graph、质量/分布等价验证和不加速区域。
