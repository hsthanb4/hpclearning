核心心智模型

1. 浮点格式动态范围与精度对比

在现代大模型训练与推理中，算力演进的核心主线是不断降低数值位宽（从 FP32 到 FP16/BF16，再到 FP8 甚至 FP4）。但位宽的降低直接带来了动态范围（Dynamic Range）与有效精度（Precision）的剧烈缩减：

主流低精度浮点格式底层位分布
FP32：1 + 8 指数 + 23 尾数
范围 ~1e-38 到 ~3e38
BF16：1 + 8 指数 + 7 尾数
范围同 FP32，精度低
FP16：1 + 5 指数 + 10 尾数
范围 ~6e-5 到 65504，易上溢
FP8 E4M3：1 + 4 + 3
最大 448，用于前向与权重
FP8 E5M2：1 + 5 + 2
最大 57344，常用于反向梯度

图 4-1：现代 GPU 核心浮点数据格式位宽与动态范围对比

  • BF16 成为主流的原因：保留了与 FP32 完全相同的 8 位指数，上溢阈值与 FP32 相同（约 3.4×10383.4 \times 10^{38}），在大模型预训练中很少上溢，但并非不会溢出：超过该范围同样得到 Inf；
  • FP8 的主要挑战：FP8 E4M3 的最大值仅为 448，最小规格化数为 2−6≈0.01562^{-6} \approx 0.0156，最小非规格化数为 2−9≈0.001952^{-9} \approx 0.00195，可表示的动态范围只有约 5 个数量级。在深度 Transformer 中，许多层的激活值与梯度很容易超出这一微小的窗口，必须配合高频的动态缩放系数（Scale Factor）。

2. 典型现象：下溢静默清零与 NaN 级联传播

现象一：下溢与 Flush-to-Zero (FTZ) 导致的静默停止学习

FTZ（Flush to Zero） 指把非规格化数（Subnormal）直接当作 0 处理。CUDA 编译默认 -ftz=false，FP32 运算会保留非规格化数；只有使用 --use_fast_math（隐含 -ftz=true）或显式 -ftz=true 时才会冲刷为零。 - 下溢是否发生首先取决于数据格式：梯度值 10−810^{-8} 在 FP32 和 BF16 中都是正常的规格化数；在 FP16 中，它低于最小非规格化数 2−24≈5.96×10−82^{-24} \approx 5.96 \times 10^{-8}，无论是否开启 FTZ 都会舍入为 0。这正是 FP16 训练必须使用 Loss Scaling 的原因； - 开启 FTZ 后，落在非规格化区间的值也会被直接清零，进一步扩大下溢范围； - 后果：代码完全不报错，但底层权重梯度全部变成了 0，模型发生静默欠拟合（Silent Stagnation），消耗了大量算力却没有进展。

现象二：单个 NaN 引发全模型级联雪崩

NaN 级联雪崩扩散链条
某一层激活上溢为 Inf
(如 FP16 超过 65504)
Inf × 0 或 Inf − Inf 产生 NaN
Softmax 输入含 NaN
全行输出全变 NaN
反向传播梯度全为 NaN
一次 update 摧毁全模型所有参数

图 4-2：局部异常引发全模型级联 NaN 污染过程

  • Inf 与 NaN 的来源：NaN 需要 Inf × 0、Inf − Inf、0/0 或负数开方等无效运算产生。LayerNorm 的 1/sqrt(var + eps) 在 eps > 0 时最大只有 1/eps1/\sqrt{\text{eps}}（eps = 1e-5 时约 316），不会产生 Inf；真正的风险是用 E[x2]−E[x]2E[x^2] - E[x]^2 计算方差时舍入出负数，使 var + eps < 0，开方得到 NaN；
  • IEEE 754 污染特性：绝大多数算术运算遇到 NaN 结果仍为 NaN（x + NaN = NaN，x * NaN = NaN）。但也有例外：IEEE 754 的 minNum/maxNum 与 CUDA 的 fmaxf/fminf 在一个操作数为 NaN 时返回另一个操作数，pow(NaN, 0) = 1。因此用 fmaxf(x, 0) 实现的 ReLU 会把 NaN 变成 0，悄悄吞掉异常，让溯源更困难；
  • 一旦某一层产生了一个非法的浮点数，只需短短几个算子，经过一次梯度更新，整个模型的参数都会被 NaN 污染。

代码实战：轻量级数值异常探针与动态缩放守卫

在工业级大规模训练系统中，直接在每一步插入 torch.isnan(x).any() 会引发严重的 CPU-GPU 同步阻塞气泡。高效的做法是：利用异步非阻塞统计，跟踪数值张量的动态最大值与异常计数，并在检测到突发下溢或 NaN 趋势时自动触发缩放保护与告警。

def audit_tensor_numerics(layers_data, target_fp_max=448.0, underflow_thresh=1e-4):
    first_nan = None
    reports = {}
    
    for layer_name, tensor in layers_data.items():
        # 1. 检测 NaN 与 Inf
        is_nan = np.isnan(tensor)
        has_nan = bool(np.any(is_nan))
        has_inf = bool(np.any(np.isinf(tensor)))
        
        if has_nan and first_nan is None:
            first_nan = layer_name
            
        # 2. 统计下溢比例 (排除 NaN/Inf 与纯绝对 0)
        valid_mask = ~(is_nan | np.isinf(tensor))
        abs_vals = np.abs(tensor[valid_mask])
        non_zero_mask = abs_vals > 0
        non_zero_count = np.sum(non_zero_mask)
        
        if non_zero_count > 0:
            underflow_count = np.sum((abs_vals > 0) & (abs_vals < underflow_thresh))
            underflow_ratio = float(underflow_count / non_zero_count)
            max_val = float(np.max(abs_vals))
        else:
            underflow_ratio = 0.0
            max_val = 0.0
            
        # 3. 计算最优量化缩放系数 (Scale = FP_MAX / (Max_Val + eps))
        optimal_scale = float(target_fp_max / (max_val + 1e-12)) if max_val > 0 else 1.0
        
        reports[layer_name] = {
            "has_nan": has_nan,
            "has_inf": has_inf,
            "underflow_ratio": underflow_ratio,
            "optimal_scale": optimal_scale
        }
        
    return {
        "first_nan_layer": first_nan,
        "layer_reports": reports
    }

Q1 参考答案

  1. 离群值（Outliers）与动态范围撕裂： 在大语言模型各层激活中，存在极少数特征通道的数值比其他正常通道大几个数量级（例如正常值在 0.1∼1.00.1 \sim 1.0，而离群值高达 50∼10050 \sim 100）。 如果采用整个 Tensor 共享一个缩放系数（Tensor-wise）：为了防止最大离群值在 FP8（最大 448）中上溢，缩放因子必须根据最大值设定（448/100=4.48448 / 100 = 4.48）。正常值 0.1 缩放后为 0.448，仍在 E4M3 规格化范围内（最小规格化数约 0.0156，最小非规格化数约 0.00195），并不会变成 0。损失主要在精度上：E4M3 只有 3 位尾数、约 5 个数量级的动态范围，大部分范围被离群值占用；原值小于约 0.0035 的元素缩放后进入非规格化区，相对精度明显下降，只有比离群值小约 5～6 个数量级（原值约 2×10−42 \times 10^{-4} 以下）的元素才会下溢为 0。分布跨度大的激活与梯度中，这些误差累积会损害收敛。
  2. 1×1281 \times 128 分块的信噪比局部隔离： DeepSeek-V3 对激活按每个 Token 的每 128 个 Channel（1×1281 \times 128）划分 Tile，对权重按 128×128128 \times 128 分块，每块拥有自己的 Scale。离群值只影响所在的 128 个元素，其他分块可以使用更大的 Scale，把数值映射到 FP8 中精度较好的区间。DeepSeek-V3 报告该方案相对 BF16 基线的训练损失相对误差低于 0.25%。

Q2 参考答案

  1. 内积方差膨胀与极值发散： 假设 Query 与 Key 向量的每个分量是均值为 0、方差为 1 的独立随机变量。其内积 q⋅k=∑i=1dkqikiq \cdot k = \sum_{i=1}^{d_k} q_i k_i 的均值为 0，方差为 dkd_k。当 dk=128d_k=128 时，标准差高达 128≈11.3\sqrt{128} \approx 11.3。未经缩放的内积打分会出现大量绝对值大于 30~50 的极大极小值。
  2. Softmax 饱和与梯度消失： 当 Softmax 输入存在巨大差异时，输出概率分布会退化为一个极度尖锐的 One-Hot 分布（最大值接近 1.0，其余全为 0.0）。此时 Softmax 的导数 Si(δij−Sj)S_i(\delta_{ij} - S_j) 趋近于 0，反向传播的梯度消失，模型无法继续学习；同时极大值直接逼近甚至超越低精度的指数表示极限，引发数值溢出。除以 dk\sqrt{d_k} 强制将方差重新归一化为 1，确保了数值处在平缓、梯度健康的活跃区间。

Q3 参考答案

  1. GPU 片上原子更新标志位： 在 CUDA Kernel 内部（或反向传播梯度更新算子中），每个线程在完成计算后，利用轻量级内置检查（isnan / isinf）。一旦发现非法数值，立即通过原子操作将显存中一个固定的 1 字节标志位（如 gpu_nan_flag）置为 1。该过程完全在 GPU 片上完成，不与 CPU 产生任何同步通信。
  2. 与梯度通信 AllReduce 异步重叠： 在每步反向传播最后进行全机群梯度 AllReduce 时，顺便将这个 1 字节标量打包随同集合通信异步归约。在执行优化器 optimizer.step() 前，CPU 仅在读取 Step 完成信号时统一检查一次状态：若标志位被置位，直接跳过当前步的权重更新（Drop Step）并打印告警快照，消除了每层检测带来的 Host-Device 气泡。

## 核心心智模型

### 1. 浮点格式动态范围与精度对比

在现代大模型训练与推理中，算力演进的核心主线是不断降低数值位宽（从 FP32 到 FP16/BF16，再到 FP8 甚至 FP4）。但位宽的降低直接带来了**动态范围（Dynamic Range）与有效精度（Precision）的剧烈缩减**：

```{=html}
<div class="fd fd-flow" role="img"><div class="fd-stack"><div class="fd-comp fd-td"><div class="fd-sg" data-nid="Formats" data-depth="0"><div class="fd-sg-title">主流低精度浮点格式底层位分布</div><div class="fd-stack"><div class="fd-comp fd-td"><div class="fd-rank"><div class="fd-node fd-box" data-nid="FP32">FP32：1 + 8 指数 + 23 尾数<br>范围 ~1e-38 到 ~3e38</div><div class="fd-node fd-box" data-nid="BF16">BF16：1 + 8 指数 + 7 尾数<br>范围同 FP32，精度低</div><div class="fd-node fd-box" data-nid="FP16">FP16：1 + 5 指数 + 10 尾数<br>范围 ~6e-5 到 65504，易上溢</div><div class="fd-node fd-box" data-nid="FP8_E4M3">FP8 E4M3：1 + 4 + 3<br>最大 448，用于前向与权重</div><div class="fd-node fd-box" data-nid="FP8_E5M2">FP8 E5M2：1 + 5 + 2<br>最大 57344，常用于反向梯度</div></div></div></div></div></div></div></div>
```
<p class="caption" align="center"><em>图 4-1：现代 GPU 核心浮点数据格式位宽与动态范围对比</em></p>

- **BF16 成为主流的原因**：保留了与 FP32 完全相同的 8 位指数，上溢阈值与 FP32 相同（约 $3.4 \times 10^{38}$），在大模型预训练中很少上溢，但并非不会溢出：超过该范围同样得到 Inf；
- **FP8 的主要挑战**：FP8 E4M3 的最大值仅为 **448**，最小规格化数为 $2^{-6} \approx 0.0156$，最小非规格化数为 $2^{-9} \approx 0.00195$，可表示的动态范围只有约 5 个数量级。在深度 Transformer 中，许多层的激活值与梯度很容易超出这一微小的窗口，必须配合高频的动态缩放系数（Scale Factor）。

---

### 2. 典型现象：下溢静默清零与 NaN 级联传播

#### 现象一：下溢与 Flush-to-Zero (FTZ) 导致的静默停止学习

**FTZ（Flush to Zero）** 指把非规格化数（Subnormal）直接当作 0 处理。CUDA 编译默认 `-ftz=false`，FP32 运算会保留非规格化数；只有使用 `--use_fast_math`（隐含 `-ftz=true`）或显式 `-ftz=true` 时才会冲刷为零。
- 下溢是否发生首先取决于数据格式：梯度值 $10^{-8}$ 在 FP32 和 BF16 中都是正常的规格化数；在 FP16 中，它低于最小非规格化数 $2^{-24} \approx 5.96 \times 10^{-8}$，无论是否开启 FTZ 都会舍入为 0。这正是 FP16 训练必须使用 Loss Scaling 的原因；
- 开启 FTZ 后，落在非规格化区间的值也会被**直接清零**，进一步扩大下溢范围；
- **后果**：代码完全不报错，但底层权重梯度全部变成了 0，模型发生**静默欠拟合（Silent Stagnation）**，消耗了大量算力却没有进展。

#### 现象二：单个 NaN 引发全模型级联雪崩

```{=html}
<div class="fd fd-flow" role="img"><div class="fd-stack"><div class="fd-comp fd-lr"><div class="fd-sg" data-nid="NaNCascade" data-depth="0"><div class="fd-sg-title">NaN 级联雪崩扩散链条</div><div class="fd-stack"><div class="fd-comp fd-td"><div class="fd-rank"><div class="fd-node fd-box" data-nid="Div0">某一层激活上溢为 Inf<br>(如 FP16 超过 65504)</div></div><div class="fd-gap" style="--gl:44px;--gt:38px"></div><div class="fd-rank"><div class="fd-node fd-box" data-nid="MatMul">Inf × 0 或 Inf − Inf 产生 NaN</div></div><div class="fd-gap" style="--gl:44px;--gt:38px"></div><div class="fd-rank"><div class="fd-node fd-box" data-nid="Softmax">Softmax 输入含 NaN<br>全行输出全变 NaN</div></div><div class="fd-gap" style="--gl:44px;--gt:38px"></div><div class="fd-rank"><div class="fd-node fd-box" data-nid="AllWeights">反向传播梯度全为 NaN<br>一次 update 摧毁全模型所有参数</div></div></div></div></div></div></div><i class="fd-e" data-s="Div0" data-t="MatMul" data-k="solid" data-h="1" data-b="0"></i><i class="fd-e" data-s="MatMul" data-t="Softmax" data-k="solid" data-h="1" data-b="0"></i><i class="fd-e" data-s="Softmax" data-t="AllWeights" data-k="solid" data-h="1" data-b="0"></i></div>
```
<p class="caption" align="center"><em>图 4-2：局部异常引发全模型级联 NaN 污染过程</em></p>

- **Inf 与 NaN 的来源**：NaN 需要 Inf × 0、Inf − Inf、0/0 或负数开方等无效运算产生。LayerNorm 的 `1/sqrt(var + eps)` 在 `eps > 0` 时最大只有 $1/\sqrt{\text{eps}}$（eps = 1e-5 时约 316），不会产生 Inf；真正的风险是用 $E[x^2] - E[x]^2$ 计算方差时舍入出负数，使 `var + eps < 0`，开方得到 NaN；
- **IEEE 754 污染特性**：绝大多数算术运算遇到 NaN 结果仍为 NaN（`x + NaN = NaN`，`x * NaN = NaN`）。但也有例外：IEEE 754 的 minNum/maxNum 与 CUDA 的 `fmaxf`/`fminf` 在一个操作数为 NaN 时返回另一个操作数，`pow(NaN, 0) = 1`。因此用 `fmaxf(x, 0)` 实现的 ReLU 会把 NaN 变成 0，悄悄吞掉异常，让溯源更困难；
- 一旦某一层产生了一个非法的浮点数，只需短短几个算子，经过一次梯度更新，整个模型的参数都会被 NaN 污染。

```python
def audit_tensor_numerics(layers_data, target_fp_max=448.0, underflow_thresh=1e-4):
    first_nan = None
    reports = {}
    
    for layer_name, tensor in layers_data.items():
        # 1. 检测 NaN 与 Inf
        is_nan = np.isnan(tensor)
        has_nan = bool(np.any(is_nan))
        has_inf = bool(np.any(np.isinf(tensor)))
        
        if has_nan and first_nan is None:
            first_nan = layer_name
            
        # 2. 统计下溢比例 (排除 NaN/Inf 与纯绝对 0)
        valid_mask = ~(is_nan | np.isinf(tensor))
        abs_vals = np.abs(tensor[valid_mask])
        non_zero_mask = abs_vals > 0
        non_zero_count = np.sum(non_zero_mask)
        
        if non_zero_count > 0:
            underflow_count = np.sum((abs_vals > 0) & (abs_vals < underflow_thresh))
            underflow_ratio = float(underflow_count / non_zero_count)
            max_val = float(np.max(abs_vals))
        else:
            underflow_ratio = 0.0
            max_val = 0.0
            
        # 3. 计算最优量化缩放系数 (Scale = FP_MAX / (Max_Val + eps))
        optimal_scale = float(target_fp_max / (max_val + 1e-12)) if max_val > 0 else 1.0
        
        reports[layer_name] = {
            "has_nan": has_nan,
            "has_inf": has_inf,
            "underflow_ratio": underflow_ratio,
            "optimal_scale": optimal_scale
        }
        
    return {
        "first_nan_layer": first_nan,
        "layer_reports": reports
    }

# 执行验证
np.random.seed(42)
t_embed = np.random.normal(0, 0.5, size=(100, 100))
t_layer1 = np.random.normal(0, 1e-5, size=(100, 100))
t_layer2 = np.copy(t_embed)
t_layer2[10, 20] = np.nan
t_layer3 = t_layer2 * 2.0
mock_layers = {
    "embed": t_embed,
    "layer1_norm": t_layer1,
    "layer2_attn": t_layer2,
    "layer3_ffn": t_layer3
}
res = audit_tensor_numerics(mock_layers, target_fp_max=448.0, underflow_thresh=1e-4)
assert res["first_nan_layer"] == "layer2_attn"
assert res["layer_reports"]["embed"]["has_nan"] == False
```

### Q1 参考答案

1. **离群值（Outliers）与动态范围撕裂**：
   在大语言模型各层激活中，存在极少数特征通道的数值比其他正常通道大几个数量级（例如正常值在 $0.1 \sim 1.0$，而离群值高达 $50 \sim 100$）。
   如果采用整个 Tensor 共享一个缩放系数（Tensor-wise）：为了防止最大离群值在 FP8（最大 448）中上溢，缩放因子必须根据最大值设定（$448 / 100 = 4.48$）。正常值 0.1 缩放后为 0.448，仍在 E4M3 规格化范围内（最小规格化数约 0.0156，最小非规格化数约 0.00195），并不会变成 0。损失主要在精度上：E4M3 只有 3 位尾数、约 5 个数量级的动态范围，大部分范围被离群值占用；原值小于约 0.0035 的元素缩放后进入非规格化区，相对精度明显下降，只有比离群值小约 5～6 个数量级（原值约 $2 \times 10^{-4}$ 以下）的元素才会下溢为 0。分布跨度大的激活与梯度中，这些误差累积会损害收敛。
2. **$1 \times 128$ 分块的信噪比局部隔离**：
   DeepSeek-V3 对激活按每个 Token 的每 128 个 Channel（$1 \times 128$）划分 Tile，对权重按 $128 \times 128$ 分块，每块拥有自己的 Scale。离群值只影响所在的 128 个元素，其他分块可以使用更大的 Scale，把数值映射到 FP8 中精度较好的区间。DeepSeek-V3 报告该方案相对 BF16 基线的训练损失相对误差低于 0.25%。

### Q2 参考答案

1. **内积方差膨胀与极值发散**：
   假设 Query 与 Key 向量的每个分量是均值为 0、方差为 1 的独立随机变量。其内积 $q \cdot k = \sum_{i=1}^{d_k} q_i k_i$ 的均值为 0，方差为 $d_k$。当 $d_k=128$ 时，标准差高达 $\sqrt{128} \approx 11.3$。未经缩放的内积打分会出现大量绝对值大于 30~50 的极大极小值。
2. **Softmax 饱和与梯度消失**：
   当 Softmax 输入存在巨大差异时，输出概率分布会退化为一个极度尖锐的 One-Hot 分布（最大值接近 1.0，其余全为 0.0）。此时 Softmax 的导数 $S_i(\delta_{ij} - S_j)$ 趋近于 0，反向传播的梯度消失，模型无法继续学习；同时极大值直接逼近甚至超越低精度的指数表示极限，引发数值溢出。除以 $\sqrt{d_k}$ 强制将方差重新归一化为 1，确保了数值处在平缓、梯度健康的活跃区间。

### Q3 参考答案

1. **GPU 片上原子更新标志位**：
   在 CUDA Kernel 内部（或反向传播梯度更新算子中），每个线程在完成计算后，利用轻量级内置检查（`isnan` / `isinf`）。一旦发现非法数值，立即通过原子操作将显存中一个固定的 1 字节标志位（如 `gpu_nan_flag`）置为 1。该过程完全在 GPU 片上完成，不与 CPU 产生任何同步通信。
2. **与梯度通信 AllReduce 异步重叠**：
   在每步反向传播最后进行全机群梯度 AllReduce 时，顺便将这个 1 字节标量打包随同集合通信异步归约。在执行优化器 `optimizer.step()` 前，CPU 仅在读取 Step 完成信号时统一检查一次状态：若标志位被置位，直接跳过当前步的权重更新（Drop Step）并打印告警快照，消除了每层检测带来的 Host-Device 气泡。
